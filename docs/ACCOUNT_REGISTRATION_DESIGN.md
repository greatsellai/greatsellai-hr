# 账户注册与邮箱验证设计

## 目标

把当前“创建账号后直接进入工作台”的流程改为可运营的自助注册闭环：用户创建独立工作区，收到一次性验证邮件，验证邮箱后才可以访问候选人、简历、JD 和 AI 能力。每个成功验证的新工作区获得 30 天进阶版试用，以及累计 1,000 次大模型调用额度。

本设计只覆盖注册和邮箱验证。找回密码将复用同一邮件发送接口和一次性令牌约束，在下一项工作中接入。

## 用户流程

1. 用户在 `/register` 填写企业或团队名称、姓名、工作邮箱和密码。
2. 服务端创建用户、独立工作区及管理员成员关系，工作区不含任何其他租户的数据。
3. 服务端生成仅保存摘要的一次性邮箱验证令牌，并向该邮箱发送验证链接。
4. 浏览器显示“请验证邮箱”页。未验证账号可以重发验证邮件或退出，但不能访问业务 API。
5. 用户打开链接，前端将令牌提交到验证接口。服务端核验令牌、写入 `email_verified_at`、在邮件链接所在浏览器建立会话并自动进入工作台；发起注册的原页面也会发现已验证状态并自动进入工作台。
6. 30 天试用从注册时开始计算，验证是进入工作台的前置条件，不会让用户因等待邮件而丢失额外试用时间。
7. 试用额度从注册时按工作区快照为 1,000 次。简历提取、评分、总结、JD 处理、JD 匹配和招聘助手使用的所有 Provider、模型与备用路由统一计入。

## 试用大模型调用额度

- 计量单位是一次真实的大模型 Provider 调用，不是一次浏览器点击或一次业务任务。Agent 工具循环、同一目标的重试、以及配置的备用模型调用均分别计一次。
- 服务端在 AI Gateway 发起外部请求前以工作区为条件原子预扣额度，并在同一事务内写入对应的调用账本。第 1,001 次不会向 Provider 发出请求，也不会生成伪造的 Provider 调用账本。
- 路由、凭据、能力、请求结构等本地校验失败发生在出站调用前，不消耗额度。当前模型网关中的每次 Provider 调用都计入，`service_kind` 只是报表字段，不能绕过额度；未来独立 OCR transport 如不属于大模型调用，必须使用单独且经审计的传输边界。
- 额度与 Provider、模型、套餐功能开关相互独立。它不能被前端参数、Provider 名称或切换模型绕过，也不会因平台管理员后来修改套餐目录而追溯改变已注册工作区的快照。
- 额度耗尽后，工作区仍可查看、筛选、下载、删除和管理已有数据；仅需要新的大模型调用的功能返回稳定的额度已用尽提示。试用到期或工作区被停用时，后台排队任务也不得继续发起模型调用。
- 前端从会话读取服务端计算的已用、上限和剩余次数，并在工作区打开时定期刷新；页面不自行计算或信任浏览器计数。

## 安全与隔离

- 验证令牌只以 SHA-256 摘要存储，原始令牌只存在于本次邮件链接中。
- 令牌 24 小时失效、仅可使用一次；重发会废止之前未使用的令牌。
- 重发对同一账号设置冷却时间和每日上限，避免被用作邮件轰炸工具。
- 同一账号的“重发”和“完成验证”会锁定用户行，并由数据库保证同一时刻最多保留一条可用验证链接；并发请求不能绕过“仅最新链接有效”的约束。
- 验证链接不会静默替换当前浏览器中另一账号的工作区会话。已登录不同账号时，接口会拒绝本次兑换，用户需先退出或使用独立浏览器会话。
- 公共注册在数据库中按全局、客户端和邮箱三类时间窗口限流；客户端和邮箱只存 HMAC 摘要，不存原始 IP 或邮箱。转发 IP 仅在直接代理地址被明确配置为可信时才会读取。
- 会话中继续保存用户、成员和工作区三元身份。所有业务 API 在原有工作区隔离后，再要求邮箱已验证。
- 旧版迁移工作区和既有平台兼容登录不受此门禁影响，避免锁住历史数据。
- 邮件验证接口不返回其他用户、工作区、简历或候选人信息。

## 邮件服务

外发验证邮件与收取简历的 IMAP 是两套服务。腾讯云 SES API 已是支持的事务发信 Provider；飞书 SMTP 仅保留为兼容回退：

- 飞书：创建独立公共邮箱，例如 `noreply@greatsell.ai`，开启其 SMTP 服务，使用飞书生成的专用密码；不得使用个人邮箱或简历收件 IMAP 凭据。
- 腾讯云 SES：发件域建议使用独立子域，例如 `mail.greatsellai.net`；使用审核通过的两份事务邮件模板。两份模板都只接收 `token` 和 `expires_minutes`：HTML 中必须保留固定公开域名和路由，验证链接为 `https://hr.greatsellai.net/verify-email?token={{token}}`，重置链接为 `https://hr.greatsellai.net/reset-password?token={{token}}`。不得传入或使用整条 `verify_url` / `reset_url` 变量，避免模板审核无法确认跳转域名。两份模板不可复用，避免将不同的一次性动作混淆。
- 应用从环境读取 Provider、发件地址、公开应用地址和对应 Provider 凭据；所有密码、API 密钥都只通过环境变量提供，绝不写入仓库或数据库。
- 生产反向代理部署还需显式配置可信代理网段，才会按真实浏览器 IP 限流；未配置时系统会安全地按直接代理连接并叠加全局限流。
- Provider 未配置或发送失败时，注册不会获得业务访问权，页面会明确提示重发或稍后重试。

切换腾讯云 SES 时，生产环境必须设置：`RESUME_V3_TRANSACTIONAL_EMAIL_PROVIDER=tencent_ses`、`RESUME_V3_TRANSACTIONAL_EMAIL_FROM`、`RESUME_V3_PUBLIC_APP_URL`、`TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`、`TENCENT_SES_REGION`、`TENCENT_SES_VERIFICATION_TEMPLATE_ID`、`TENCENT_SES_PASSWORD_RESET_TEMPLATE_ID`、`RESUME_V3_EMAIL_CREDENTIALS_KEY` 和 `RESUME_V3_TRUSTED_PROXY_CIDRS`。Compose 会把必要运行配置同时传给 API 与 worker；密钥仅存在于被 Git 忽略的生产环境文件中。注册/重发由 API 发送，找回密码由 worker 处理加密 outbox。缺少任一 SES 模板、发件地址或凭据时，进程会拒绝启动；未完成配置时，注册接口不得创建无法验证的账号。

## API

- `POST /v1/auth/register`：创建待验证账号与工作区，建立仅用于验证页的会话，并发送验证邮件。
- `POST /v1/auth/email-verification/complete`：兑换验证令牌并激活工作台访问。
- `POST /v1/auth/email-verification/resend`：当前待验证会话重发验证邮件。
- `GET /v1/auth/session`：新增 `email_verified` 和 `email_verification_required`，前端据此显示验证页而非工作台；试用工作区还返回服务端计算的 `llm_call_limit`、`llm_call_used` 和 `llm_call_remaining`。
- `GET /v1/auth/registration-offer`：返回当前默认试用套餐的天数和固定的 `llm_call_limit=1000`，仅供注册页展示，实际额度以工作区快照为准。

## 验收与回归

- 注册创建的新工作区与其他工作区完全隔离。
- 未验证会话无法读取、上传或匹配任一业务数据。
- 正确令牌只能使用一次；过期、篡改或已废止令牌均不能激活账号。
- 验证成功后，邮件链接页和发起注册的原页面都会自动进入各自已建立会话的工作台。
- 重发遵守限频且只保留最新有效令牌。
- 已登录工作区不会被其他账号的验证链接覆盖；并发重发或验证后，数据库中仍至多存在一条可用链接。
- 不同邮箱和伪造转发头都不能绕开公共注册的持久化限流。
- 邮件发送调用不记录令牌、密码、候选人信息或密钥。
- 旧版兼容工作区、已验证账号、登录、试用与跨租户测试继续通过。
- 第 1,000 次真实大模型调用可完成，第 1,001 次在 Provider 请求前被拒绝；不同 Provider、重试、备用路由和 Agent 多轮均计入同一工作区额度。
- 一个工作区的额度耗尽不会影响另一个工作区；未出站的本地校验失败不消耗额度，额度耗尽不会自动删除候选人数据。
