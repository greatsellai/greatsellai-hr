# 条件筛选 V2

筛选 V2 只查询当前激活、状态为 `ready` 且来源文本可靠的简历。AI 负责从原文提取事实，后端负责证据校验、归一化和确定性匹配；筛选结果不代表拒绝、录用或最终招聘决定。

## 接口

- `GET /v1/filter-options`：返回版本化筛选项及前端显示顺序。
- `POST /v1/candidates/search`：接受 `candidate_filter.v2` 请求，同时兼容旧筛选字段。
- `POST /v1/resumes/{resume_id}/enrich-filter-facts`：为历史活跃简历排队补充 V2 事实。任务按事实版本加锁，只增量合并来源可验证的新字段。
- `/v1/saved-filters`：保存、读取和删除完整 V2 请求；旧筛选器仍可读取。

## 固定语义

- 顶层启用的筛选模块按 AND；模块内的多选项默认按 OR。
- 同一个教育条件中的院校、专业、层级、GPA 和排名必须由同一条教育经历满足；经历条件同理。
- 成绩支持最低平均分、最低 GPA 百分比、最高名次和排名前百分比；数值必须能在引用的原文块中找到，否则不保存、不命中。
- 最高学历选项不展示“初中、其他、未知”，院校层级不展示“其他、未知”；数据库仍保留缺失状态，缺失事实不匹配肯定条件。
- 新筛选器使用每条教育经历的 `institution_classifications_any_of`：985、211、本科、大专、中专、海外院校。`211` 严格排除 985；同一候选人的多段教育可分别显示多个真实标签。
- 旧 `is_985_211` 与 `institution_tiers_any_of` 仅为兼容读取保留。旧的肯定 `is_985_211=true` 显式迁移为“985 或 211”；旧的否定/未知或旧多层级条件不自动伪造为新分类。
- 应届由最高教育经历毕业年月是否位于用户选择的窗口内确定；毕业年月缺失不命中应届或往届。
- 985/211 仅使用受控历史教育部名单和别名；普通本科/大专仅使用版本化教育部全国高等学校名单。中专、海外院校必须有简历原文中与该学校相邻的明确证据；暑校、培训、交换、访学、短期或未知学历记录不归类，英文校名、学历写“本科”或不在国内名单中均不能推断分类。模型给出的 985/211 roster ID 只有在与原文学校名精确一致时才可作为本地关联辅助，不能单独产生正向标签。985 不再带 211 标签。
- 英语证书使用稳定代码和中英文名称。四级、英语四级、大学英语四级、CET4、CET-4、CET 4 均归一为 `cet4`；专四只归一为 `tem4`。证书之间按 OR，最低分必须由同一证书记录满足。
- 泛匹配为任意关键词命中；英语别名先归一到已验证的证书代码，避免 CET-4 与 TEM-4 子串串线。精准匹配要求所有输入短语按规范化后的连续文本出现，不扩展别名。
- 未写奖学金、竞赛奖项、英语证书或成绩时状态为未知，不能解释为明确的“没有”。
- 经历获奖级别、获奖结果、奖学金级别，以及班级/校内组织/社团/项目组/公司的领导角色均为非必选；肯定条件只匹配带原文证据的事实。
- 招聘 Agent 的 `search_candidates` 工具暴露同一套 V2 参数并调用同一个确定性搜索服务，不维护第二套筛选规则。

## 发布检查

提交 PR 前运行：

```bash
python -m pytest -q
cd web
npm ci
npm run build
```

包含迁移的生产发布必须先备份 PostgreSQL。部署和回滚均只使用已合并 `main` 的 `prod-*` 标签，不删除数据库、PDF、环境变量或 Docker 卷。
