# 简历筛选 V3 — 全项目实施计划

**对应 PRD：** docs/PRD.md  
**执行原则：** 先保证数据正确、可追溯和可复核，再做评分与自动化体验。  
**当前阶段：** V3 招聘闭环、注册登录、工作区数据隔离、三档套餐与 AI Gateway 已实现；当前建设独立的平台管理员控制台。旧数据不迁移，AI 结论继续受字段级证据约束。

## 实施状态（2026-07-16）

已落地的代码基础：

- 独立 V3 后端、SQLite 本地开发与 PostgreSQL 云端目标；旧项目和旧 `resume_text` 不参与迁移。
- 仅 PDF 的上传、哈希、原生文本提取、页数/文本质量门槛和 `needs_review` 异常状态。
- 结构化教育/经历/技能事实、证据块校验、项目/竞赛不能误算为正式工作、自动入库审计。
- 985/211 历史名单、受控别名、2026 教育部全国普通高校名单与 AI 规则文档；后端将每条教育经历归为 985、211、本科、大专、中专、海外院校之一或未知。211 严格排除 985，未命中不伪造为负面类别。
- 条件筛选、关键词、稳定游标、命中证据引用、保存筛选器和候选人复核详情 API。
- 简历库 API 与桌面端汇总表：全部上传版本可见，展示 AI 总结预览、最新 AI 评分、处理状态与原 PDF；提取中自动刷新，空总结/空评分明确标识。
- 不可变事实快照，作为后续评分、总结和 JD 匹配唯一的 AI 输入来源。
- Alembic 迁移、显式院校名单初始化、Docker Compose/Caddy 云端部署骨架。

已实现：多格式简历入库、可配置 AI 评分、AI 总结、版本化 JD 匹配、邮箱收件、用户/工作区隔离、审计元数据与云部署骨架。OCR 仍按文件质量按需使用，不作为普通文本文件的强制前置依赖。

## 1. 总体策略

V3 按独立项目建设，旧项目只作为业务参考，不复制其简历数据和解析结果。开发顺序必须遵循以下依赖关系：

    原始文件与版本
        → 解析质量
        → 结构化事实与证据
        → 条件筛选
        → 评分 / 总结 / JD 匹配

这样可以避免先做一个看起来完整、实际建立在脏 resume_text 上的评分系统。

## 3. M0：需求冻结与质量基线

### 工作项

1. 确认 PRD 中的首期范围和非范围：仅 PDF、单账号、无共享、云服务器部署、首期不依赖 OCR。
2. 确认筛选字段、经历类型、学历枚举、技能标准化规则。
3. 建立无隐私的测试简历集：

   - 文字层 PDF。
   - 扫描件 PDF。
   - 多页 PDF。
   - 双栏/复杂布局 PDF。
   - 含项目、竞赛、实习、正式工作的简历。
   - 学校简称、历史名称、非 985/211 学校的简历。

4. 编写人工标注答案：页数、教育、经历类型、技能、985/211、工作月数。
5. 定义质量指标、自动证据门槛和异常处理规则。

### 基线指标

| 指标 | 定义 | 首期建议门槛 |
| --- | --- | --- |
| 页覆盖率 | 解析页数 / 源 PDF 页数 | 100% 才可自动 ready |
| 文本可读率 | 非空、非乱码页占比 | 100% 才可自动 ready |
| 教育字段准确率 | 学校/学历/专业与人工标注一致 | 目标 ≥ 95% |
| 经历类型准确率 | 正式工作、实习、项目、竞赛分类正确 | 目标 ≥ 95% |
| 工作年限误算率 | 项目/竞赛被计入工作年限的比例 | 目标 0 |
| 985/211 准确率 | 归一化匹配结果准确 | 目标 100% |

### 退出条件

- 产品负责人确认 PRD。
- 测试集与人工标注完成。
- 质量指标写入自动化测试和发布门槛。

## 4. M1：工程骨架与开发规范

### 工作项

1. 初始化独立 V3 仓库。
2. 建立推荐技术结构：

   - frontend：React + TypeScript。
   - backend：FastAPI。
   - database：PostgreSQL（云服务器生产环境；开发阶段可使用 SQLite）。
   - object storage：本地目录（开发）和云对象存储/S3 兼容存储（生产）。
   - background worker：解析、模型调用和批量任务。

3. 建立云服务器 Docker Compose、HTTPS 反向代理、数据库备份、日志和健康检查。
4. 配置环境变量、密钥管理、数据库迁移、测试、格式化和静态检查。
5. 实现单账号认证、审计日志和健康检查；不建设角色、成员或团队共享模型。
5. 定义 API 错误结构、分页、任务状态和 ID 规范。

### 退出条件

- 本地一条命令可启动前后端。
- CI 至少执行单元测试、类型检查和格式检查。
- 不包含真实简历、真实 API Key 或生产数据库文件。

## 5. M2：可信的简历入库与解析

### 工作项

1. 实现候选人和简历版本表。
2. 实现仅 PDF 的上传、大小/类型/文件头校验、SHA-256 和对象存储。
3. 实现原生 PDF 文本提取，并记录：

   - 源页数。
   - 解析页数。
   - 每页文本量。
   - 总文本量。
   - 乱码比例。
   - 解析器和版本。

4. 实现质量状态机：uploaded、extracting、text_ready、needs_review、ready、failed。
5. 扫描件、图片型 PDF、漏页和文字异常统一转 `needs_review` 异常状态；提供重新上传或重试，不接入 OCR Provider。
6. 实现错误重试、幂等上传、重复文件识别和任务取消。
7. 实现解析详情页：显示状态、质量原因和原始文件。

### 必做测试

- 多页 PDF 不得只解析第一页后 ready。
- 空白/扫描 PDF 进入 needs_review。
- 解析失败不会替换旧 ready 版本。
- 重复上传不产生文件覆盖或数据串线。

### 退出条件

- 测试集中的正常 PDF 均通过页覆盖校验。
- 异常文件均落到正确状态。
- 原文件和版本关系可审计。

## 6. M3：结构化事实、证据与自动启用

### 工作项

1. 建立 source block、教育、经历、技能、聚合筛选事实等表。
2. 将文本/版面输出整理为稳定的块 ID、页码和坐标。
3. 定义严格的模型输入输出 Schema：

   - 只提取明确事实。
   - 每项必须选择证据块。
   - 姓名是唯一例外：仅可从候选人本人明确的页眉或“姓名/Name”字段提取，并必须携带原文页码证据；电话、邮箱、地址等仍禁止输出。
   - AI 按随请求注入的版本化历史 985/211 规则文档给出二值初判和 roster ID；服务端只在 roster ID 与原文学校名精确对应时将其作为本地关联辅助，分类仍由服务端名册和事实证据决定，不能因模型 ID 单独产生正向结论。
   - 每段工作、实习、项目、竞赛均输出经历名称、担任角色和逐条职责/贡献；每条职责单独选择原文证据块。

4. 接入 DeepSeek Provider：

   - 服务端读取密钥。
   - 使用 Schema/工具调用约束。
   - 保存脱敏任务元数据，避免记录原文和密钥。
   - 为网络失败、限流、无效 JSON 设置可重试/异常处理状态。

5. 实现确定性后处理：

   - 学校别名归一化。
   - 教育经历级院校分类与兼容 `is_985_211` 汇总计算。
   - 学历、日期、技能键归一化。
   - 工作月数计算。
   - 经历类型语义门槛。

6. 实现只读的结构化事实/原 PDF 查看、任务重试与审计记录；不设置人工确认或手工修正入口。

### 必做测试

- 项目/竞赛角色不能写入 employment。
- 明确的公司实习可写入 internship。
- 字段值和证据块不一致时，该字段不能进入 ready；无可用字段时整份简历不能 ready。
   - 学校无法归一化时保存为未知，不依赖人工确认，也不能把未知当作“非 985/211”。
- 985、211-only、普通本科、大专、中专、海外、未知及别名样本均按证据和名册正确归类。

### 退出条件

- 所有可搜索字段均有证据。
- 成功提取自动建立筛选索引；异常简历可重试或重新上传而不影响现有索引。
- 测试集达到 M0 指标。

## 7. M4：条件筛选 MVP

### 工作项

1. 实现候选人搜索 API。
2. 支持筛选 V2：最高学历、精确院校类型（985、211、本科、大专、中专、海外院校）与简称、应届窗口、经历和技能分类、英语证书/分数、奖学金、竞赛获奖、成绩排名、领导经历及泛/精准关键词。
3. 实现 AND/OR 语义和同记录约束。
4. 默认只查询 active + ready 的简历。
5. 返回命中理由，不返回全文或敏感信息。
6. 实现 React 筛选页、结果页、候选人详情、原 PDF 和只读结构化事实入口。
7. 实现保存筛选器与 URL 分享。
8. 添加数据库索引、分页和基础排序。
9. 为历史活跃简历提供版本保护的按需 V2 补充提取，增量合并后生成新事实快照。

### 验收场景

- “985 + 本科专业 + Python + SQL + 正式工作不少于 24 个月”可正确返回；精确 211 筛选不得包含 985。
- 两段不同教育经历不能拼成一个错误命中。
- 项目经历不影响“正式工作不少于 24 个月”。
- 异常候选人默认不出现，界面提示待处理数量并提供上传页重试入口。

### 退出条件

- 业务方可用筛选页完成一轮真实候选人初筛。
- 每条命中均可解释。

## 8. M5：评分与简历总结

### 工作项

1. 实现评分模板、维度、权重校验和版本管理。
2. 实现 AI 维度分析和后端确定性加权计算。
3. 实现评分详情、重算、手工调整和审计。
4. 实现总结生成、编辑、版本管理和重新生成。
5. 用同一份结构化事实作为评分和总结输入，避免重复直接解析 PDF。

### 验收场景

- 权重不为 100 时不能发布模板。
- 修改权重后总分按公式变化，维度证据不丢失。
- 总结不新增原文不存在的关键经历。

### 退出条件

- 业务方能创建通用评分模板并批量查看候选人分数。
- 每个分数和总结可追溯到简历与模板版本。

## 9. M6：JD 匹配

### 工作项

1. 实现 JD 创建、编辑和版本管理。
2. 提取 JD 必须条件、加分条件、技能、经验、学历和专业要求。
3. 实现候选人对特定 JD 的匹配分析。
4. 明确区分“关键不满足”“信息不足”“加分项未命中”。
5. 支持在筛选结果中按 JD 匹配分排序，但不替代筛选条件。

### 验收场景

- 缺少必须技能时必须显示关键不满足。
- 匹配理由能够同时定位 JD 条款和简历证据。
- JD 更新后旧匹配结果保留历史版本，新结果重新计算。

### 退出条件

- 招聘人员可从一个岗位 JD 查看候选人匹配列表和差距。

## 10. M7：上线、质量与运营

### 工作项

1. 注册登录、成员角色、工作区隔离、下载审计、数据删除与保留策略；所有业务 API、Worker 与原文件访问按工作区强制校验。
2. 模型成本、失败率、解析质量、字段剔除率和重试率监控。
3. 性能测试：上传并发、搜索响应、批量重算。
4. 安全测试：文件类型绕过、路径遍历、权限越权、密钥泄露、日志泄露。
5. 建立生产备份、恢复演练、告警和 Runbook。
6. 小范围试运行，收集异常样本和字段剔除反馈，迭代院校别名和提示词。

### 退出条件

- 达到性能、安全和质量门槛。
- 试运行中没有严重漏页、工作年限误算或越权问题。
- 管理员可处理常见失败、重试和重新上传任务。

## 10.1 M8：平台管理员控制台

详细设计见 [平台管理员控制台设计](PLATFORM_ADMIN_CONSOLE_DESIGN.md)。该控制台是 GreatSell 内部运营能力，不计入 A/B/C 套餐权益。

### 工作项

1. 在认证会话中返回服务端 `is_platform_admin`，增加独立 `/platform` 路由守卫和侧栏；平台权限不受当前工作区试用或套餐状态阻断。
2. 实现只含运营元数据的总览、工作区列表/详情和用户列表/详情，不查询或返回候选人、简历、JD、评分、邮箱内容、Prompt、模型输出与原文件。
3. 复用三档套餐和 AI Gateway 控制面，提供套餐编辑、工作区套餐/状态/试用调整、普通账号启停、Provider/模型/价格版本、路由发布和安全用量报表。
4. 新增不可变平台审计事件；关键写入保存操作者、动作、目标、原因、请求 ID 与脱敏前后差异，并与业务变更同事务提交。
5. 禁止停用当前操作者或其他平台管理员；不实现用户冒充、租户会话接管、硬删除、真实密钥管理或服务器运维。
6. 完成桌面 master-detail 和响应式降级：`>=1200px` 展开侧栏，`768–1199px` 图标轨道，`<768px` 顶部按钮与侧栏抽屉；筛选条件跨布局保留。
7. 为后续订阅预留价格版本、订阅、支付事件和 Entitlement 分层，但本阶段不接入收款、退款、开票或支付方式。

### 必做测试

- 匿名、工作区管理员、招聘官和平台管理员的平台 API 权限矩阵。
- 平台管理员不能借助身份读取其他工作区业务资源或原文件；平台响应 Schema 无招聘内容和秘密字段。
- 工作区、用户、套餐与 AI 配置变更均有正确审计；失败与重复提交不会造成部分写入或重复版本。
- 停用自己或其他平台管理员被拒绝；普通账号启停和工作区状态变化符合规则。
- 1440px、1024px、768px、375px 的前端关键路径与错误状态通过自动化浏览器测试。

### 退出条件

- 平台运营人员可完成总览、工作区/用户/套餐维护、AI 配置和审计追溯，而无法查看任一候选人或招聘业务正文。
- 后端完整 pytest、前端生产构建、平台权限/脱敏/重复提交回归和 `git diff --check` 通过。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 单一解析器漏页/漏字 | 筛选、评分全面失真 | 页数与文本质量门槛；异常文件不自动入库；后续再依据真实样本评估 OCR |
| 模型幻觉或经历误分类 | 错算工作年限、错误筛选 | Schema、证据校验、经历类型门槛、负例测试 |
| 学校别名不全 | 985/211 误判 | 版本化院校表、严格精确别名匹配、别名管理 |
| API 限流或模型失败 | 任务堆积 | 异步队列、重试、Provider 抽象、状态可见 |
| 简历隐私泄露 | 合规和信任风险 | 最小化传输、权限、脱敏日志、审计、删除机制 |
| 旧数据质量差 | 错误迁移造成技术债 | 不迁移为可筛事实；仅保留旧系统独立运行 |
| 评分被过度相信 | 不公平或招聘风险 | 展示证据和不确定性；不允许自动拒绝 |
| 平台管理员越权 | 跨租户隐私和控制面风险 | 独立平台依赖、安全响应 Schema、业务 API 不提权、不可变审计与越权测试 |
