# 招聘 Agent 会话上下文与 LangGraph 编排

## 目标

让招聘人员能够自然地继续上一轮工作，例如“在刚刚 RAG 匹配度 100% 的人中，按当前 JD 选最匹配的候选人”或“把上一句的行业经验改成必须项”。系统保存短期、可见的聊天正文来理解指代，同时不把简历原文、工具结果或浏览器提交的候选人 ID 当作可信上下文。

## 数据边界

每个会话仅保存以下受控状态，默认有效期为 24 小时：

- 当前用户、当前工作区与当前 JD 的不透明 ID；
- 当前人才画像与当前画像版本的不透明 ID；
- 一个服务端创建的候选集合；
- 候选集合来源：普通 Agent 筛选结果，或人才画像搜索运行；
- 集合中的简历 ID 与顺序；
- 上下文版本号，用于阻止两个浏览器标签静默覆盖“刚刚这些人”。
- 最近 12 个成功完成的对话回合：HR 输入的正文、最终展示给 HR 的 Markdown 回复，以及最多 12 项有长度边界的本轮处理摘要（工具显示名与面向 HR 的结果概述）。

对话正文是受同一工作区、会话创建者和 24 小时无操作 TTL 保护的短期敏感数据。它只保存已成功完成的“用户输入 + 最终可见回复”成对记录，以及服务端生成、字段受限的工具显示名和结果摘要；后者不进入模型上下文。它不保存 system/hidden Prompt、LangGraph 内部消息、原始 tool call、工具参数或工具 JSON、候选人卡片和 ID 列表、简历原文、来源证据块、邮件正文或 Provider 原始载荷。若最终可见回复本身提到候选人姓名，该文本仅在这段短期、私有会话中可见，不额外复制候选人卡片或来源数据。人才画像实体自身为可审计而保存原始找人需求；会话只引用该实体，不复制其原始需求或内容。会话默认仅创建者可读；同工作区共享需要未来显式授权，不能隐式开启。

新建或修订人才画像会清除旧候选集合，避免将旧结果误当成新条件的结果。过期状态不仅不可读取，worker 还会按工作区重新校验后物理删除会话、候选集合和集合成员；它不会删除独立保存的人才画像、版本或已执行的搜索运行。清理扫描仅读取不透明会话 ID 与工作区 ID。

自由文本续写时，浏览器只能传递 `conversation_id` 和 `context_version`；它不传画像或版本 ID。受控上下文接口可从卡片操作绑定当前工作区内的 `talent_search_profile(profile_id, revision_id)` 或确认后的 `talent_search_run(run_id)`。浏览器、模型工具和 URL 都不能提交 `resume_ids`、`candidate_ids` 或任意历史消息。

## 运行图

```text
prepare → model ──无工具──→ finalize
              │
              └─有工具→ tools ──画像生命周期──→ finalize
                              └──其他受控工具──→ model/finalize
```

- `prepare`：验证当前用户/工作区会话，绑定合法人才画像或运行，解析当前 JD 与当前画像，读取最近最多 6 个已完成对话回合，并生成本轮临时上下文。历史仅用于理解“刚才、上一句、这个、再加一条”等指代，任何候选人事实仍必须通过当前工作区工具核验。
- `model`：通过既有 AI Gateway 调用模型；每轮最多四次工具循环，单条模型回复最多四个工具调用。
- `tools`：服务端声明的 `draft_talent_search_profile` 和 `refine_active_talent_search_profile` 用于自然语言起草/修订画像。新找人需求或“再加 985、年限改 5 年”等补充条件先走这两个工具；它们只产生草案，且与候选人搜索、读取、评分、JD 匹配、确认和启动运行互斥。普通筛选、评分、JD 匹配和邮箱工具继续受控执行；搜索结果会成为下一轮可用的候选集合。
- `finalize`：写入受控工作状态，并在最终回复成功后原子保存本轮可见的用户/助手正文和有边界的安全处理摘要，再返回 Markdown。失败、工具异常或版本冲突不会留下半条对话。

LangGraph 不配置 checkpointer。持久化真相仍是带组织范围约束的数据库模型；LangGraph 仅编排单个 HTTP 回合。短期回合表不是 checkpoint，不保存图内消息、原始工具调用或工具载荷；仅保留供 HR 阅读的有边界安全处理摘要。

## 当前 JD 下的上下文工具

- `get_current_job_ranking_from_active_context`：只读取当前已保存集合的 JD 匹配。未完成匹配必须显示为待处理，不能当作低分或不符合。
- `start_current_job_match_for_active_context`：只为当前已保存集合请求 JD 匹配任务；后续排名仍强制按该集合过滤。

当上下文来自人才画像运行时，工具可接受仅限 `0–100` 的 RAG 展示分阈值。`100` 使用与人才画像界面相同的派生分数，并保留一位小数显示的边界容差。

如果用户明确指向“刚刚筛选的人”“这些人”“人才画像/RAG 结果”等当前范围，服务端会把误选的全工作区 JD 排名或匹配工具重定向到上下文工具；这不是依赖提示词的约定。

## API 契约与前端接入

`POST /v1/recruiting-agent/turns` 返回 `conversation_id`、`context_version`、安全上下文摘要、最近对话回合、每轮安全处理摘要与需要展示的画像卡。首次回合不传版本；后续回合携带 `conversation_id` 时必须同时携带最新 `context_version`。直接描述想找的人时，LangGraph 先生成画像草案；后续自由文本根据服务端保存的当前画像版本和短期对话回合修订草案，而不是由前端选择“新建/补充”模式。数据库行锁与乐观版本共同阻止两个标签页静默覆盖范围。

`POST /v1/recruiting-agent/conversations/context` 可在不调用模型的前提下，把当前工作区内的画像版本或确认后的 `talent_search_run` 设为 Agent 工作范围。它同样使用会话版本保护，并且只接受受控的 profile/revision 或 run ID；前端不能借此提交候选人 ID 或简历内容。绑定历史运行时只保留“这些候选人”的范围，不保留可被继续修订的画像，防止误改无关草案。

已提供 `GET` / `DELETE /v1/recruiting-agent/conversations/{id}` 供前端恢复或清除会话。前端只在 `sessionStorage` 保存按“工作区 + 用户”分隔的不透明会话 ID；刷新后由服务端恢复最近 12 个短期对话回合、当前候选范围、JD 摘要、安全画像摘要和每轮安全处理摘要，并通过正常工作区授权重新读取画像卡。浏览器不会保存或回传聊天正文，接口也不会恢复候选人 ID、简历内容、图内消息、原始工具调用或模型工具载荷。删除会话或 24 小时无操作后的清理会级联物理删除全文与候选范围。画像仍需招聘人员明确确认并点击开始找人，才能读取候选人或启动任何匹配工作。

会话不存在、已过期、跨工作区或非所有者访问统一按不可访问处理；上下文版本过期返回冲突，前端先重新读取当前安全摘要再允许用户重试。
