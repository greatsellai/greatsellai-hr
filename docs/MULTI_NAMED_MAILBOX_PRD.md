## 1. 背景与现状

一个招聘工作区通常同时使用多个收件地址，例如“算法社招”“校招”“销售岗”或“猎头转发”。现有收件能力已经能安全地接收新邮件、处理失败附件并按原邮件精确重试，但工作区内只有一个有效邮箱配置：接口和页面均以单一 `/v1/mailbox/*` 资源为中心。

本需求把“收件邮箱”升级为工作区中的多个独立、可命名的收件通道。每个通道独立保存连接配置、授权码、收件起点、水位线、同步状态和附件审计；它们把简历送进同一个工作区的简历库，但不得混淆来源、共享凭据或跨工作区访问数据。

本 PRD 的“名称”指 HR 自定义的业务标签，例如“AI 算法社招”，不是候选人姓名、邮箱别名或 AI 提取结果。

## 2. 目标与非目标

### 2.1 目标

1. 一个工作区可创建多个命名收件通道，并可单独启用、暂停、同步和归档。
2. 新建通道可选择仅接收绑定后的新邮件，或首次回溯最近指定天数的邮件；首次范围完成后，每个通道均以独立的 IMAP UIDNEXT、UIDVALIDITY 和同步水位线持续接收新邮件。
3. 每份入库附件、重试记录和最终简历都可追溯到来源通道；简历库可按来源通道筛选。
4. 每个通道沿用现有多格式文件入库、文本提取、AI 事实提取、失败附件精确重试和工作区隔离链路。
5. 一个通道连接或处理失败，不影响同一工作区的其他通道继续收件。
6. 为后续套餐配额预留能力，但本期不把固定邮箱数量写死在前端。

### 2.2 非目标

- 不扫描用户未明确选择的绑定前历史邮件，也不提供无上限的全量邮箱回扫。
- 不自动回复候选人、不发送拒信、邀约或 Offer。
- 不以发件人邮箱、邮件主题或收件别名推断候选人身份、岗位归属或招聘结论。
- 不基于文件名、姓名或附件哈希自动合并来自不同通道的候选人。
- 不引入跨工作区共享邮箱、共享候选人库或跨工作区搜索。
- 不支持把一个失败附件改从另一收件通道重试。

## 3. 核心概念与业务规则

### 3.1 收件通道

收件通道（以下简称“通道”）是一个工作区拥有的经审核服务商收件配置，包含：

- HR 填写的通道名称；
- 服务商标识、系统固定的 IMAPS 主机与端口、接收邮箱和文件夹；
- 仅服务端可读的加密授权码，或 OAuth 授权状态与加密 refresh token；
- 独立的首次回溯天数、固定的首次回溯起始日期和完成时间，以及收件起点、UIDVALIDITY、同步时间和错误状态；
- 独立的邮件暂存留存策略、清理记录和失败附件重试副本；
- 启用、暂停或归档状态。

通道名称在同一工作区内唯一。创建时去除首尾空格，按大小写和连续空白归一化后校验；名称长度为 1 至 32 个可见字符。不同工作区可使用相同名称。

### 3.2 通道状态

- `enabled`：后台轮询和手动同步均可执行。
- `paused`：保留配置、审计和水位线，不再自动同步；恢复后从原水位线继续。
- `syncing`：一次同步正在执行，仅表示瞬时运行状态，不替代 `enabled`/`paused`。
- `error`：最近一次同步失败；通道仍可由管理员修复后重新同步。
- `archived`：停止接收且不再可编辑连接身份；历史附件、简历来源和审计仍可查看。

归档优先于删除。首期不提供物理删除通道的入口，以免破坏历史附件、失败重试和简历来源追溯。

### 3.3 连接身份、授权方式与改名

通道名称可以随时修改，不影响已入库简历、附件幂等或失败重试。

正常产品流程中，管理员选择经审核的邮箱服务商，系统固定其 IMAPS 主机和 TLS `993` 端口；前端不提供任意主机或端口输入。服务商、接收邮箱和文件夹共同构成连接身份。连接身份一旦已经产生附件记录，前端不得直接覆盖；用户应归档旧通道并新建通道。这样可以保留旧附件的原始来源快照，避免重绑后误取另一邮箱中的邮件。

服务商本身不能在既有通道上原地切换；要使用另一服务商时，管理员必须新建目标通道。这避免把旧服务商的授权码错误发送给新的服务商。

飞书、腾讯企业邮箱和 QQ 邮箱使用服务商提供的授权码或客户端专用密码；更新时不显示旧值，也不重置收件起点。Gmail/Google Workspace 与 Microsoft 365/Outlook 通过 OAuth 授权，系统不收集登录密码；重新授权只替换服务端加密保存的 refresh token。新建通道时，HR 可选择从当前时刻开始，或首次回溯最近指定天数。IMAP 按自然日回溯，选择“最近 7 天”表示当天与此前 6 个自然日。回溯范围在绑定时固化，后台完成后立即切换为仅接收新邮件；编辑、重新授权和恢复通道均不得扩大或重置已选范围。若用户明确重绑一个尚无入库记录的通道，系统按其既有首次范围重新读取水位线。

OAuth 的生产回调统一为 `https://hr.greatsellai.net/v1/mailbox-oauth/callback`。兼容入口 `https://greatsellai.net/greatsellhr/` 可以发起授权，但完成后回到主入口；后端用短期、安全的浏览器关联 Cookie、一次性 state、PKCE、当前工作区和管理员成员关系共同校验，不放宽普通登录 Cookie 的 `SameSite=Strict` 策略。回调 URL、服务商 OAuth 客户端配置和公共应用入口必须指向同一受控主入口；不满足时安全拒绝开始授权。

已有旧版原始 IMAP 接口仅保留一个兼容发布周期：它仍须通过服务端精确白名单和 TLS 安全校验，但不再是新建通道的浏览器入口，也不得借此新增任意网络端点。

如果 IMAP 返回的 UIDVALIDITY 与通道保存值不一致，系统将该通道标记为来源已变化并停止继续抓取；不得静默重置水位线或复用旧 UID。管理员必须按“新建/重绑通道”的安全流程确认后，才可从新的当前位置继续收件。

## 4. 用户流程

### 4.1 创建第一个或新增通道

1. 工作区管理员进入“邮箱附件入库”。
2. 点击“新增收件邮箱”。
3. 填写通道名称、选择经审核的服务商、接收邮箱和文件夹，并选择首次范围：从现在开始，或最近有限天数；对于授权码服务商填写授权码，对于 OAuth 服务商跳转至 Google 或 Microsoft 完成授权。
4. 服务端校验固定端点连接、读取该文件夹的 UIDNEXT 与 UIDVALIDITY，并加密保存授权码或 OAuth refresh token。
5. 页面显示首次范围和导入状态。选择回溯时，后台只处理冻结日期范围内的邮件；完成后切换为仅接收新邮件。
6. 新通道出现在通道列表中，默认启用。

### 4.2 日常收件与查看来源

1. Worker 按通道分别拉取新附件。
2. 每份附件复用标准入库链路，产生候选人、简历、AI 提取任务和附件审计。
3. 收件页显示每个通道的最近同步、错误、待处理数量和最近入库记录。
4. 简历库展示来源标签；用户可筛选“手动上传”或某一个收件通道。
5. 来源标签只说明系统收件入口，不作为评分、JD 匹配或自动筛选条件。

### 4.3 暂停、恢复与归档

- 暂停一个通道只停止该通道的后台同步，不影响其他通道。
- 若首次有限回溯尚未完成，恢复后继续同一个已冻结的日期范围；其他情况继续从暂停前的水位线拉取，不扩大或补扫绑定前历史。
- 归档前要求管理员确认；归档后保留历史记录、关联简历和错误审计，但不再允许同步。

### 4.4 失败附件重试

失败附件仍在其原通道内重试。服务端必须校验该通道的来源指纹、UIDVALIDITY、邮件 UID 和附件 SHA-256；不得从其他通道、同一封邮件的其他附件或新绑邮箱中替代原附件。

如果通道已经归档、授权码不可用、来源身份改变或邮件已不可读，重试安全失败，并明确提示下一步（例如恢复原通道或请候选人重新发送）。

## 5. 体验与界面要求

### 5.1 收件页信息架构

收件页保留桌面端高信息密度布局，新增“收件通道”列表或选择器：

- 顶部可切换“全部通道”与单个通道；
- 每个通道显示：名称、接收邮箱、状态、最近同步时间、最近异常和本期入库数；
- 提供“新增收件邮箱”“同步此通道”“暂停/恢复”“归档”和“编辑名称/授权码”操作；
- “立即同步”在选择单个通道时只同步该通道；在“全部通道”视图中可触发安全的逐通道同步，并显示分别结果；
- 附件历史表增加“来源通道”列，并支持按通道过滤；
- 失败行仍展示稳定失败原因、尝试次数、最后处理时间和“重新入库”。

不得在列表、通知、URL、Agent 对话记录或浏览器日志中展示授权码。接收邮箱仅对有邮箱管理权限的工作区成员可见；普通简历库默认只显示通道名称。

### 5.2 简历库来源筛选

简历库新增“入库来源”筛选：

- `全部来源`；
- `手动上传`；
- 当前工作区各已存在通道的名称（包括已归档通道）。

同一候选人可拥有来自不同通道的多个简历版本。系统保留每个版本的来源，不因为名称、文件名或哈希相同而自动合并候选人。

### 5.3 空、加载和错误状态

- 尚未配置通道：引导新增首个收件邮箱。
- 全部通道暂停：明确说明“不会自动接收新附件”。
- 单通道连接失败：在该通道上显示错误，不遮挡其他通道状态。
- 同步中：仅禁用该通道重复同步；不禁用其他通道操作。
- 归档通道：历史可查看，所有会改变收件状态的操作禁用并说明原因。

状态文字必须与颜色、图标共同表达；所有按钮支持键盘操作和明确焦点。

## 6. 数据模型与迁移设计

### 6.1 `mailbox_configs`

保留现有 `mailbox_configs` 作为通道主表，并扩展为一对多工作区关系。关键字段：

- `id`、`organization_id`；
- `display_name`、`display_name_key`；
- 保留 `enabled`（`false` 即暂停）和新增 `archived_at`；`syncing` 由同步租约推导，`error` 由 `last_sync_error` 推导，不新增含义重叠的状态字段；
- `provider_key`、`authentication_mode`、`imap_host`、`imap_port`、`email_address`、`mailbox`；其中新通道的端点由 `provider_key` 固定；
- `encrypted_password`（仅授权码服务商，密文）与独立的 OAuth 凭据表（仅 OAuth 服务商，密文 refresh token）；两种凭据不得混存或向浏览器回显；
- `initial_sync_lookback_days`、`initial_backfill_since_date`、`initial_backfill_completed_at`，以及 `import_start_uid`、`imap_uidvalidity`、`import_started_at`；
- `last_synced_at`、`last_sync_error`；
- 每通道同步租约字段（令牌、开始时间、过期时间），用于防止后台 Worker 与手动同步并发处理同一通道；
- 创建、更新时间和归档时间。

约束与索引：

- 唯一：`(organization_id, display_name_key)`；
- 建议唯一：同一工作区中相同规范化连接身份不可重复创建；
- 索引：`(organization_id, status)`、通道同步租约、`(organization_id, last_synced_at)`；
- 所有 ORM 查询和写入必须带当前 `organization_id`，不能依赖通道 ID 单独授权。

OAuth 连接意图是独立、短期的一次性记录：保存 state 摘要、加密 PKCE verifier、当前工作区、当前管理员成员关系和过期时间，不保存浏览器中的原始 state、授权 code 或 access token。OAuth 凭据、连接意图和通道表均按 `organization_id` 隔离。

### 6.2 简历与附件来源

`email_attachment_imports` 已通过 `mailbox_config_id` 关联来源通道，且其附件幂等唯一键必须继续包含通道 ID、消息 UID 与附件哈希。

为让简历库无需依赖临时邮件记录判断来源，新增或明确以下稳定来源字段：

- 简历版本的 `ingestion_source_type`：`manual_upload` 或 `mailbox_attachment`；
- 简历版本的 `source_mailbox_config_id`（手动上传为 `null`）；
- 可选的 `source_mailbox_label_snapshot`，用于通道归档或改名后的历史审计。

来源字段只作追溯与筛选用途，不得成为 AI 评分、JD 匹配或候选人自动判定的模型输入。

### 6.3 迁移现有单通道数据

1. 保留既有 `mailbox_configs.id`，不得重加密、重抓取或清空授权码与水位线。
2. 为每个现有通道补写名称“默认收件邮箱”；如同一工作区存在多个历史配置，则按稳定顺序命名“默认收件邮箱 1 / 2 …”。
3. 既有 `email_attachment_imports` 和失败重试记录继续通过原 `mailbox_config_id` 工作，不迁移到新 ID。
4. 为既有邮箱入库的简历回填来源；无法可靠关联时标记为 `mailbox_legacy_unknown`，不伪造具体通道名称。
5. 迁移完成后保留旧单邮箱 API 一个兼容发布周期：仅在工作区只有一个未归档通道时代理到该通道；存在多个通道时返回明确的弃用错误，避免静默选择“最新一个”。

## 7. 接口契约

新接口统一使用复数资源，所有接口均要求已认证的当前工作区上下文。

- `GET /v1/mailboxes`
  - 返回当前工作区的通道列表和聚合状态；不返回授权码。
- `GET /v1/mailbox-providers`
  - 返回经审核服务商的展示信息、可用性和授权方式；不返回任何凭据、OAuth client secret 或 token。
- `POST /v1/mailboxes`
  - 创建授权码服务商通道、连通性校验并记录新通道的首次入库范围与收件起点；端点必须与所选服务商一致。
- `POST /v1/mailbox-oauth/start`
  - 为当前管理员和当前工作区创建一次性 OAuth 授权意图，返回仅用于浏览器跳转的服务商授权 URL。
- `GET /v1/mailbox-oauth/callback`
  - 仅处理服务商回调；校验短期浏览器关联、当前工作区、管理员成员关系、session version、state、PKCE 和过期时间后创建通道或更新 OAuth 授权，最终只重定向回收件页，不在页面或 URL 中返回 token。响应必须设置 `Cache-Control: no-store` 与 `Referrer-Policy: no-referrer`。
- `POST /v1/mailboxes/{mailbox_id}/oauth/reauthorize`
  - 为当前工作区中已有的 OAuth 通道发起重新授权；不能改变其已入库来源身份或水位线。
- `GET /v1/mailboxes/{mailbox_id}`
  - 返回单通道配置和状态；不返回授权码。
- `PATCH /v1/mailboxes/{mailbox_id}`
  - 修改名称、启用状态或授权码；连接身份变更遵循第 3.3 节的安全规则。
- `POST /v1/mailboxes/{mailbox_id}/sync`
  - 只同步指定通道。
- `POST /v1/mailboxes/sync`
  - 管理员触发全部已启用通道的逐通道同步，返回每个通道独立结果。
- `POST /v1/mailboxes/{mailbox_id}/archive`
  - 归档通道，不删除历史数据。
- `GET/PUT /v1/mailboxes/{mailbox_id}/retention`
  - 查看或修改该通道的邮件暂存留存策略；绝不按“最新通道”推断目标。
- `POST /v1/mailboxes/{mailbox_id}/retention/preview`
  - 仅预览该通道当前可清理的暂存内容。
- `POST /v1/mailboxes/{mailbox_id}/retention/cleanup`
  - 仅清理该通道已到期的邮件暂存副本；不会触及候选人原始简历。
- `GET /v1/mailboxes/{mailbox_id}/retention/runs`
  - 查看该通道的清理运行记录。
- `GET /v1/mailbox-imports?mailbox_id={id}`
  - 返回当前工作区附件记录；`mailbox_id` 为可选过滤条件。
- `POST /v1/mailbox-imports/{import_id}/retry`
  - 保留现有精确重试语义，服务端从附件记录反查原通道，不接受客户端指定替代通道。

错误语义：跨工作区、不存在或已不可访问资源统一返回 `404`；状态冲突（同步中、已归档、不可重试）返回 `409`；配置校验问题返回稳定的 `422` 错误码。接口不得返回授权码、邮件正文、发件人地址或原始异常栈。

## 8. 同步、幂等与可靠性

1. Worker 先领取一个通道的短期租约，再在该通道所属工作区上下文中执行 IMAP 操作和写入。
2. 一个通道一次只允许一个自动或手动同步；不同通道可以独立运行，单通道异常不得中断同工作区其他通道。
3. 调度应公平轮转各启用通道，避免高流量通道长期占用 Worker。
4. 每个通道独立使用 UIDNEXT、UIDVALIDITY 和 import watermark。只有新建时明确选择的有限日期范围可以首次回溯；回溯以 IMAP 内部日期搜索并分批完成，完成后水位线切到当时的 UIDNEXT，严格只扫描后续新邮件。
5. 同一通道内以通道 ID、邮件 UID 和附件 SHA-256 幂等；重复轮询、页面刷新和重复点击不得创建重复简历。
6. 两个不同通道收到完全相同的附件时，分别保留两条收件审计，并标记为“可能重复来源”；不得仅凭哈希自动合并候选人或覆盖来源。
7. 失败附件精确重试保留原通道的来源指纹、UIDVALIDITY、UID、哈希和领取令牌；通道改名不会影响重试，连接身份变更或归档不会误取其他通道邮件。
8. AI 提取任务只在附件已经安全入库后创建；AI 任务失败沿用既有队列重试，不重新从邮箱创建候选人。
9. 邮件正文、成功附件副本和失败附件重试副本按通道分别执行三档留存（最小、标准、审计）；归档通道不再收件，但其到期暂存内容仍由后台清理，候选人原文件和已入库事实不受此策略影响。
10. 新建通道只能选择部署方审核的服务商，系统固定其 TLS IMAPS `993` 端点；保存、首次校验、后台同步和精确重试均再次校验。旧版兼容接口同样只能使用部署方配置的精确白名单。服务端拒绝 IP 字面量、私网/回环解析结果、混合 DNS 结果和 DNS 重绑定目标，并以原始主机名完成 TLS SNI 与证书校验。
11. Worker 对单封 RFC822 邮件、邮件头、IMAP 搜索响应、MIME part/嵌套深度、每封附件数、附件解码总量和正文暂存分别设置可配置上限。邮件全文使用有界 `BODY.PEEK` 分段读取；服务器声明或实际响应超限时，系统不下载完整邮件、不进入文件解析，写入安全的“已跳过”审计记录且后续不重复拉取该 UID。
12. 每个同步任务可在网络类故障下自行重试；连续失败按“已耗尽任务内重试的同步任务”计数，而不是按单次连接尝试计数。默认在一小时内连续 3 个终态同步任务失败时打开工作区内告警；成功同步自动恢复告警。凭据不可读、来源 UIDVALIDITY 变化或 IMAP 安全校验失败应立即打开高优先级告警。
13. 单封邮件因大小、MIME 或附件限制而被安全跳过，不产生通道故障告警；但无法安全展开整个待处理 UID 范围等会持续阻断同步的问题，纳入连续失败告警。租约竞争不计入故障告警。

## 9. 权限、隐私与 Agent 边界

- 只有工作区管理员可创建、编辑、暂停、归档、查看连接配置、手动同步和重试附件。
- 具备简历库访问权的成员可见来源标签和处理状态，但默认不能查看接收邮箱地址、IMAP 主机或任何凭据。
- 所有候选人、简历、附件记录、失败尝试、通道配置和同步任务按当前工作区过滤；通过猜测通道 ID、附件 ID 或简历 ID 均不得访问其他工作区数据。
- 授权码和 OAuth refresh token 仅加密保存在服务端；OAuth access token 只在单次 IMAP 认证内存中使用。前端、日志、通知、数据库导出样例、模型提示词和 Agent 工具结果均不得回显。
- OAuth state 必须一次性、短期有效，并同时绑定当前工作区、当前管理员和成员关系；其他工作区或其他用户访问同一 state 必须安全失败，且不能消费原拥有者的授权意图。
- 邮件正文、发件人地址和非必要邮件头不写入简历工作台，也不发送给大模型。
- 招聘 Agent 可查询当前工作区通道状态、按名称同步通道、解释失败原因；不能读取或修改授权码、归档通道、跨工作区查询，不能发送邮件或自动改变招聘结论。

## 10. 验收标准

1. 同一工作区可创建两个以上不同名称的通道，并分别显示独立状态和收件起点。
2. 两个通道均可独立选择首次范围：选择“从现在开始”时绑定前已有邮件不会被导入；选择有限回溯天数时，仅该日期范围内的邮件被分批导入，完成后新邮件只由对应通道处理。
3. 暂停或连接失败一个通道，不影响另一个启用通道的自动和手动同步。
4. 附件历史、失败原因、重试次数和简历库来源标签均能正确显示对应通道名称。
5. 在同一通道重复拉取同一邮件附件，只产生一条附件记录和一份简历；不同通道收到相同附件不自动合并候选人。
6. 失败附件重试只从原通道精确抓取原 UID 与原 SHA-256 附件；不得触发其他通道 `SEARCH` 或 `FETCH`。
7. 通道改名后既有记录仍可追溯；归档后历史可见、同步停止、凭据不可读取。
8. A 工作区无法列出、读取、同步、归档或重试 B 工作区的任何通道和附件，统一返回 `404`。
9. 前端不展示授权码；网络响应、操作日志和 Agent 工具结果不包含授权码、邮件正文或发件人地址。
10. 单通道历史数据迁移后不丢失配置、收件水位线、附件审计、失败重试或简历来源；旧接口在多通道状态下不会静默选择错误通道。
11. 后端测试覆盖多通道水位线、同通道幂等、跨通道相同附件、单通道故障隔离、跨工作区越权和归档后的重试边界；前端构建和迁移升级路径通过。

## 11. 分阶段实现建议

1. **数据与安全边界：** 扩展通道表、来源字段、迁移旧单通道数据、补齐工作区隔离和迁移测试。
2. **后端与 Worker：** 新复数 API、逐通道同步租约、公平调度、单通道手动同步、兼容旧接口。
3. **前端：** 通道列表、新增/编辑/暂停/归档、来源筛选、逐通道附件历史和错误状态。
4. **回归与发布：** 验证现有单通道、批量上传、AI 提取、失败附件重试、筛选、评分、JD 匹配和 Agent 均不受影响；先在无隐私测试邮箱试运行，再按发布流程上线。

## 12. 完成定义

只有当多个通道在同一工作区中能独立收件、独立故障恢复、正确标注来源，并且跨工作区不可越权、凭据不可泄露、旧单通道数据可安全迁移时，本需求才算完成。
