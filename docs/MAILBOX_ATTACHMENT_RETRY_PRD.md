# 邮箱附件失败与单附件重试 PRD

**版本：** V1.0
**日期：** 2026-07-20
**所属版本：** 高级版 B，收简历邮箱自动收集
**状态：** 已实现，待合并

## 1. 背景

邮箱入库会经历“IMAP 拉取、附件校验、原文件保存、文本提取、AI 提取任务入队”等步骤。当前失败附件会留下记录，但后续自动同步会将该邮件 UID 视为已处理，用户无法只对失败附件再次执行入库。

本需求补齐一条可追溯的恢复路径：招聘人员可以从邮箱入库记录中，对一份失败附件发起精确重试，而不是重新扫描整箱邮件，也不需要候选人立刻重发邮件。

## 2. 目标与非目标

### 2.1 目标

1. 明确展示附件的处理结果、稳定失败原因、尝试次数和最后尝试时间。
2. 仅允许对可恢复的失败附件进行单附件重试。
3. 重试必须按原邮件 UID 和附件 SHA-256 精确定位，绝不拿同一封邮件中的其他附件替代。
4. 重试复用现有“原文件保存 → 文本提取/OCR → AI 提取任务”链路。
5. 每次处理和重试保留审计历史；成功后同一附件不得重复创建候选人或简历。
6. 所有读取、重试记录、候选人、简历和 AI 任务始终限定在当前工作区。

### 2.2 非目标

- 不扫描绑定之前的历史邮件。
- 不自动回复候选人、发送拒信或改变候选人招聘结论。
- 不支持 ZIP、RAR、PPT、HEIC 等未支持格式。
- 不将邮件正文、发件人邮箱或授权码展示到简历工作台。
- 本期不做批量重试、跨邮箱迁移重试或人工修改附件内容。

## 3. 用户流程

1. 收件 Worker 自动拉取绑定后收到的新邮件附件。
2. 系统为每份附件创建一条入库记录，并记录首次处理尝试。
3. 若附件入库失败，记录表显示失败原因、尝试次数和“重试此附件”。
4. 招聘人员点击“重试此附件”。按钮进入加载状态，避免重复点击。
5. 服务端验证当前工作区、邮箱来源快照、IMAP UIDVALIDITY、邮件 UID 和附件 SHA-256。
6. 验证通过后，只重新抓取该附件，并复用标准入库流程。
7. 成功时原记录更新为“已入库”，关联新简历；失败时仍为“处理失败”，保留最新原因和完整尝试历史。

## 4. 状态与失败原因

附件入库记录状态：

- `imported`：附件已保存为简历版本，并已进入后续文本/AI 处理链路。
- `failed`：附件未能完成入库，可根据失败原因决定是否允许重试。
- `retrying`：该附件正在由一次重试请求处理，其他重试请求必须被拒绝。
- `skipped`：无可用附件、附件格式不支持或确定不应入库，不提供重试。

面向用户的失败分类至少包括：

- 邮箱连接或授权异常。
- 邮件或附件暂时无法读取。
- 文件为空、过大、损坏、伪装格式或不符合上传校验。
- 文本提取、Office 转换或 OCR 处理异常。
- 原文件存储、数据库或任务入队临时异常。
- 邮箱来源已变更、UIDVALIDITY 已变更，或原邮件附件已不可获取。

“AI 提取失败”与“附件入库失败”分开显示：附件已成功保存时，AI 任务走既有队列重试，不重复从邮箱创建候选人。

## 5. 重试规则

1. 仅当前工作区的管理员可以重试当前工作区的 `failed` 记录。
2. 同一条记录同一时间只能有一次 `retrying`；每次领取会写入不可复用的重试令牌和一条 `retrying` 审计。超过租约时间的中断重试可被安全回收，旧令牌不得覆盖新令牌的结果。
3. `skipped`、已入库记录、来源信息缺失的历史记录，以及来源已变化的记录不可重试。
4. 重试不修改邮箱绑定水位线，不扫描其他邮件，不改变其他附件记录。
5. 邮件 UID、UIDVALIDITY、邮箱来源指纹和附件 SHA-256 必须全部匹配；任一不匹配即停止，提示候选人重新发送。
6. 首次处理和每次手动重试都写入尝试审计：触发方式、序号、开始/结束时间、状态、稳定错误码和关联简历。
7. 已成功入库的附件再次点击或并发请求不得产生第二份简历。

## 6. 数据与接口

### 6.1 数据

`email_attachment_imports` 增加：

- 来源 UIDVALIDITY 与非敏感来源指纹。
- `attempt_count`、`last_attempted_at`、`updated_at`。
- 重试租约过期时间与不可复用的重试令牌。

新增 `email_attachment_import_attempts`：

- 所属工作区、所属附件入库记录、尝试序号。
- 触发方式（自动同步 / 手动重试）、状态、稳定错误码。
- 开始/结束时间和关联简历（如有）。

旧记录没有可信来源快照时保持可查看，但不开放重试，避免错误抓取重绑后的邮箱内容。

### 6.2 API

- `GET /v1/mailbox/imports`
  - 增加 `import_id`、`retryable`、`attempt_count`、`last_attempted_at`。
- `POST /v1/mailbox/imports/{import_id}/retry`
  - 只处理当前工作区的单个失败附件。
  - 成功返回更新后的附件记录。
  - 跨工作区或不存在返回 `404`；不可重试或正在处理返回 `409`。

## 7. 界面要求

邮箱入库页的“最近入库记录”保持高信息密度表格：

- 展示附件名、结果、失败原因、尝试次数、最后尝试时间和操作。
- 失败且可重试的行显示“重试此附件”。
- 处理中显示“正在重试”，按钮禁用并提供文字状态。
- 不可重试的行显示具体原因和下一步，例如“请候选人重新发送”。
- 重试成功或失败后刷新该列表并通过现有通知反馈结果。
- 所有状态不得只靠颜色表达；按钮可键盘操作，焦点状态清晰。

## 8. 验收标准

1. 一份首次入库失败的 PDF 附件，在邮件未改变时可被单独重试并成功入库。
2. 重试只执行该记录对应的 IMAP UID FETCH，不扫描或导入其他邮件。
3. 同一附件重复点击重试不会生成两份候选人或两份简历。
4. 同一封邮件包含多个附件时，重试其中一份不会影响其他附件。
5. 邮件被删除、附件哈希不符、UIDVALIDITY 或邮箱来源变化时，系统安全失败且不导入错误附件。
6. A 工作区无法读取或重试 B 工作区的附件记录，统一返回 `404`。
7. 失败原因、尝试次数和最后尝试时间在页面可见；授权码、邮件正文、发件人邮箱和原始异常栈不可见。
8. 后端测试、迁移升级测试和前端生产构建通过。
