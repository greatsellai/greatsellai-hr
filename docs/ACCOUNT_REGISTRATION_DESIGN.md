# 账户注册与邮箱验证设计

## 目标

把当前“创建账号后直接进入工作台”的流程改为可运营的自助注册闭环：用户创建独立工作区，收到一次性验证邮件，验证邮箱后才可以访问候选人、简历、JD 和 AI 能力。每个成功验证的新工作区获得 30 天进阶版试用。

本设计只覆盖注册和邮箱验证。找回密码将复用同一邮件发送接口和一次性令牌约束，在下一项工作中接入。

## 用户流程

1. 用户在 `/register` 填写企业或团队名称、姓名、工作邮箱和密码。
2. 服务端创建用户、独立工作区及管理员成员关系，工作区不含任何其他租户的数据。
3. 服务端生成仅保存摘要的一次性邮箱验证令牌，并向该邮箱发送验证链接。
4. 浏览器显示“请验证邮箱”页。未验证账号可以重发验证邮件或退出，但不能访问业务 API。
5. 用户打开链接，前端将令牌提交到验证接口。服务端核验令牌、写入 `email_verified_at`、建立会话，并进入工作台。
6. 30 天试用从注册时开始计算，验证是进入工作台的前置条件，不会让用户因等待邮件而丢失额外试用时间。

## 安全与隔离

- 验证令牌只以 SHA-256 摘要存储，原始令牌只存在于本次邮件链接中。
- 令牌 24 小时失效、仅可使用一次；重发会废止之前未使用的令牌。
- 重发对同一账号设置冷却时间和每日上限，避免被用作邮件轰炸工具。
- 同一账号的“重发”和“完成验证”会锁定用户行，并由数据库保证同一时刻最多保留一条可用验证链接；并发请求不能绕过“仅最新链接有效”的约束。
- 验证链接不会静默替换当前浏览器中另一账号的工作区会话。已登录不同账号时，接口会拒绝本次兑换，用户需先退出或使用独立浏览器会话。
- 公共注册在数据库中按全局、客户端和邮箱三类时间窗口限流；客户端和邮箱只存 HMAC 摘要，不存原始 IP 或邮箱。转发 IP 仅在直接代理地址被明确配置为可信时才会读取。
- 会话中继续保存用户、成员和工作区三元身份。所有业务 API 在原有工作区隔离后，再要求邮箱已验证。
- 旧版迁移工作区和既有平台兼容登录不受此门禁影响，避免锁住历史数据。
- 邮件验证接口不返回其他用户、工作区、简历或候选人信息。

## 邮件服务

外发验证邮件与收取简历的 IMAP 是两套服务。当前临时使用飞书公共邮箱 SMTP，后续可无迁移地切换到腾讯云 SES API：

- 飞书：创建独立公共邮箱，例如 `noreply@greatsell.ai`，开启其 SMTP 服务，使用飞书生成的专用密码；不得使用个人邮箱或简历收件 IMAP 凭据。
- 腾讯云 SES：后续发件域建议使用独立子域，例如 `mail.greatsellai.net`；使用审核通过的事务邮件模板，模板变量为 `verify_url` 和 `expires_minutes`。
- 应用从环境读取 Provider、发件地址、公开应用地址和对应 Provider 凭据；所有密码、API 密钥都只通过环境变量提供，绝不写入仓库或数据库。
- 生产反向代理部署还需显式配置可信代理网段，才会按真实浏览器 IP 限流；未配置时系统会安全地按直接代理连接并叠加全局限流。
- Provider 未配置或发送失败时，注册不会获得业务访问权，页面会明确提示重发或稍后重试。

临时飞书 SMTP 上线时，部署配置必须将下列变量传入 API 容器：`RESUME_V3_TRANSACTIONAL_EMAIL_PROVIDER=feishu_smtp`、`RESUME_V3_TRANSACTIONAL_EMAIL_FROM`、`RESUME_V3_PUBLIC_APP_URL`、`RESUME_V3_FEISHU_SMTP_HOST=smtp.feishu.cn`、`RESUME_V3_FEISHU_SMTP_PORT=465`、`RESUME_V3_FEISHU_SMTP_TLS_MODE=ssl`、`RESUME_V3_FEISHU_SMTP_USERNAME`、`RESUME_V3_FEISHU_SMTP_PASSWORD` 和 `RESUME_V3_TRUSTED_PROXY_CIDRS`。后续切 SES 时改回 `tencent_ses` 并配置 SES 区域、模板 ID 与腾讯云受控凭据即可；未完成配置时，注册接口应保持不可用，而不是创建无法验证的账号。

## API

- `POST /v1/auth/register`：创建待验证账号与工作区，建立仅用于验证页的会话，并发送验证邮件。
- `POST /v1/auth/email-verification/complete`：兑换验证令牌并激活工作台访问。
- `POST /v1/auth/email-verification/resend`：当前待验证会话重发验证邮件。
- `GET /v1/auth/session`：新增 `email_verified` 和 `email_verification_required`，前端据此显示验证页而非工作台。

## 验收与回归

- 注册创建的新工作区与其他工作区完全隔离。
- 未验证会话无法读取、上传或匹配任一业务数据。
- 正确令牌只能使用一次；过期、篡改或已废止令牌均不能激活账号。
- 重发遵守限频且只保留最新有效令牌。
- 已登录工作区不会被其他账号的验证链接覆盖；并发重发或验证后，数据库中仍至多存在一条可用链接。
- 不同邮箱和伪造转发头都不能绕开公共注册的持久化限流。
- 邮件发送调用不记录令牌、密码、候选人信息或密钥。
- 旧版兼容工作区、已验证账号、登录、试用与跨租户测试继续通过。
