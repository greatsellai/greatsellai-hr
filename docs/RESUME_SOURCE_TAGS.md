# 投递渠道标签设计

## 目标

招聘人员可以按候选人简历的投递渠道筛选，例如 BOSS 直聘、猎聘、LinkedIn 或内推；同一份简历经多个渠道进入工作区时，所有渠道都应保留。

## 概念边界

- 收件通道：系统连接的 IMAP 邮箱，例如“招聘邮箱”。它是运输路径，不等同于招聘平台。
- 投递渠道标签：根据一封邮件的发件人域名、发件人地址或主题关键词识别出的标签，例如“BOSS 直聘”。
- 邮件附件入库事件：一封邮件中的一个附件，是渠道识别的权威事实记录。
- 简历来源汇总：简历从所有关联入库事件继承的渠道并集，只用于列表、详情与筛选。

标签不直接写入候选人。候选人可能有多个简历版本，也可能同时来自 BOSS 直聘、内推和 LinkedIn；把标签写成候选人单值属性会覆盖来源事实。

## 数据模型

1. `source_tags`
   - 工作区内可用的标签定义，名称在工作区内唯一。
   - 标签可以归档，历史入库记录和简历展示仍保留其名称快照。

2. `mailbox_source_tag_rules`
   - 绑定一个收件通道与一个渠道标签。
   - 可按发件人域名、发件人地址、主题关键词组合匹配；填写的条件全部满足才命中。
   - 邮件原始发件人、主题和正文不写入数据库，规则判断只在同步内存中进行。

3. `email_attachment_import_tags`
   - 记录某个邮件附件入库事件命中了哪些标签，以及标签名称快照和规则来源。
   - 这是渠道事实的审计层。

4. `resume_source_tags`
   - 简历与渠道标签的多对多汇总关联。
   - 同一简历、同一标签只有一条记录，保存首次和最近一次关联的附件入库事件与时间。

## 入库与去重

1. IMAP 同步解析邮件头后，先匹配当前收件通道启用的规则。
2. 创建附件入库事件时，将命中的标签快照一同保存。
3. 首次导入成功时，标签写入简历来源汇总。
4. 相同附件从另一个邮件或收件通道进入时，新的附件事件仍保留自己的标签，并把标签并入已存在的简历。
5. 等待中的去重附件在其规范入库完成后，同样并入其标签。
6. 附件重试不会重新读取或重新分类邮件头，只复用原始入库事件已经保存的标签。

## 产品行为

- 筛选左栏新增“投递渠道”。多选语义固定为“任一渠道”，不受全局“全部满足 / 任一满足”切换影响。
- 候选人结果仅在姓名下展示紧凑渠道标签，不新增一整列，避免表格继续变宽。
- 候选人详情和简历版本选择器展示该版本的渠道标签。
- 邮箱设置中，收件通道概览下提供“投递渠道规则”管理区；连接邮箱与配置标签规则保持分开。
- 简历库明确区分“收件通道”和“投递渠道”。

## 隔离与隐私

- 所有标签、规则、附件事件标签与简历标签都带 `organization_id`，并由工作区查询条件强制隔离。
- 外部工作区的标签 ID 不可用于本工作区搜索、规则创建或详情读取。
- 不保存邮件正文、完整发件人地址或主题快照；只保存用户配置的规则和命中后的标签名称快照。

## 验收与测试

- 同一工作区的多封邮件可分别命中不同平台，并能按标签筛选。
- 同一附件经两个平台投递后，只生成一份简历，但简历保留两个平台标签。
- 失败附件重试后仍保留原标签。
- 跨工作区使用同名或外部标签均不串数据，也不能通过标签 ID 越权查询。
- 保存筛选、清空筛选、分页和招聘助手筛选范围均保留渠道条件。
