# 发布前安全与恢复回归测试设计

**状态：** 已批准实施
**范围：** HTML 原件安全、注册限流、找回密码、浏览器关键路径、多格式真实容器、PostgreSQL + 原文件卷成对恢复、Worker 租约恢复与生产 Compose 合约。
**边界：** 本设计不会读取或修改生产 `.env.production`、域名、DNS、服务器或候选人数据；Compose、发布脚本和 Caddy→API 网络边界的受审查代码变更在本仓库完成。

## 1. 目标与发布门槛

这组回归的目标是证明三个边界同时成立：

1. 不可信输入不能在已登录的 HR 同源页面中执行，公共认证接口的限流和找回流程不能被绕过；
2. 浏览器中的关键招聘操作可被稳定回归，且跨工作区资源不会因猜测 ID 被展示；
3. 生产运行时所依赖的容器工具、数据库迁移、原文件卷和后台任务在故障后可恢复。

每次发布前至少应通过：

- 后端完整 `pytest`；
- 前端 `npm run build`；
- Playwright 关键路径；
- Docker 镜像内多格式提取；
- 临时 PostgreSQL 的迁移、备份恢复和租约回收演练。

所有 fixture 均为合成数据，不包含候选人姓名、邮件地址、简历正文、密钥或生产备份。

## 2. HTML 原件安全

HTML 简历可以被解析为文本，但原件本身仍是不可信内容。任何读取原件的路径都必须使用同一份响应策略：

- `.html`、`.htm` 始终返回 `Content-Disposition: attachment`；
- 其响应 MIME 固定为 `application/octet-stream`，不能返回 `text/html`；
- 保留 `X-Content-Type-Options: nosniff`、`Cache-Control: no-store, private` 与无 referrer 策略；
- 该策略覆盖显式的 `view` / `download` 授权 URL 与旧兼容原件 URL；
- PDF 的受审计 inline 预览保持不变，避免把安全修复变成 PDF 体验回归。

测试会上传带脚本标记的合成 HTML，再逐一断言三条访问路径都只能下载，且 PDF 仍可 inline。测试不以“提取时 BeautifulSoup 删除脚本”代替原件访问防护。

## 3. 注册限流与 Caddy 转发

注册限流的客户端桶以真实客户端 IP 为键，但只在直连 peer 属于已配置可信代理网段时读取 Caddy 追加的 `X-Forwarded-For` 最后一段。测试以 FastAPI `TestClient` 的 TCP peer 模拟 Caddy：

- 两个不同的真实 IP 在同一个可信代理后各有独立客户端桶；
- 同一真实 IP 在超过个人阈值后被拒绝；
- 多段 `X-Forwarded-For` 只采用 Caddy 追加的最后地址；
- 未信任 peer 提供的转发头仍被忽略。

生产 Compose 把 Caddy 固定为专用 `proxy` 网络中的 `172.30.0.2`，只有 API 同时连接
该网络和内部业务网络；数据库、迁移任务和 worker 都不连接该代理网络。
`RESUME_V3_TRUSTED_PROXY_CIDRS=172.30.0.2/32` 是生产启动必填项，配置校验会拒绝空值、
全网段或公网 CIDR。CI 会以无密钥示例环境渲染 Compose 并验证这一网络与环境变量合约，
而不会访问真实环境文件。

## 4. 找回密码闭环

找回密码与邮箱验证复用事务邮件边界，但使用独立的邮件类型和 URL。公开请求还使用
持久化的全局、可信代理后的客户端、以及邮箱摘要三层限流，避免邮件轰炸或不断废止
已有有效链接：

1. 请求接口始终返回枚举安全的接受结果；对于有效账号，只在服务端签发摘要化的一次性令牌并发送邮件。
2. 测试邮件 Provider 仅在进程内保存合成投递，测试从邮件链接取得令牌；HTTP 响应、数据库、日志和前端均不回显令牌。
3. 重置完成后更新密码哈希并使令牌不可再次使用；新请求会废止同账号的旧有效令牌。
4. 前端提供 `/forgot-password` 申请页与 `/reset-password?token=...` 设置新密码页。

端到端测试覆盖：请求邮件、打开链接、设置新密码、旧密码登录失败、新密码登录成功、过期令牌拒绝、重复使用拒绝和不存在邮箱的枚举安全响应。

## 5. Playwright 关键路径

浏览器测试使用独立临时数据库和测试邮件 Provider，不连接生产 API、模型、IMAP 或 SMTP。真实后端安全规则由 Python 集成测试覆盖；浏览器测试验证页面、表单、路由、加载状态和 API 调用契约。

最低覆盖路径：

1. 注册表单校验、验证邮件页面与登录；
2. 上传合成 PDF、上传状态与筛选结果；
3. 一键批量评分的创建与进度显示；
4. 已保存 JD 的三栏匹配结果、排序与可信度信息；
5. 邮箱同步任务的提交与后台状态展示；
6. 跨工作区资源请求返回 `404`，页面不展示其他工作区的候选人或原件信息。

模型、IMAP 和长耗时任务在浏览器层使用受控测试响应；对应的服务、工作区和任务语义继续由后端集成测试及容器恢复测试验证，避免把真实外部网络作为发布门槛。

## 6. Docker 多格式提取

多格式回归必须在由项目 `Dockerfile` 构建的镜像内运行，而不是只 mock `soffice` 或 `tesseract`。临时目录将生成以下无隐私 fixture：

- PDF；
- DOCX（通过 LibreOffice 转 PDF）；
- XLSX；
- PNG 与 JPG（通过 Tesseract OCR）；
- HTML（通过 BeautifulSoup 清理脚本后提取正文）。

每个文件都验证提取成功、解析器标识正确、文本含预期的合成标记，并确认图片路径实际调用容器里的 Tesseract。该演练使用独立镜像和临时容器，不接入生产 Compose 项目或卷。

## 7. PostgreSQL 迁移、备份恢复与 Worker

恢复演练使用一次性 Docker 网络、PostgreSQL 容器、独立数据库和带标签的真实 Docker uploads 卷：

1. 从历史 Alembic revision 升级到 `head`，校验迁移图和最新表结构；
2. 写入合成工作区、简历元数据、原文件和可恢复的队列记录；
3. 使用 `pg_dump` 创建逻辑数据库备份，并以只读卷挂载打包 uploads；备份目录必须含同一 ID 的清单与 SHA-256；
4. 删除源 PostgreSQL 容器与源 uploads 卷后，恢复到新的临时 PostgreSQL 实例与新的命名卷，校验工作区归属、原文件校验和与业务记录一致；
5. 分别把邮箱后台任务和 AI 提取任务模拟为崩溃时遗留的 `running` + 过期租约，验证两套 Worker 队列都能安全重新领取，而不会跨工作区写入或领取第二工作区任务。

生产发布助手使用与演练相同的成对备份布局：每次部署/应用回滚前都暂停 API 与 worker，
发布完成前不会把 `.partial` 目录标记为可恢复备份；恢复需要显式确认并先创建当前状态的
安全备份。运行权限、保留期限和异地副本仍由部署负责人按部署 Runbook 管理。

## 8. 测试分层与提交边界

| 层级 | 产物 | 外部依赖 |
| --- | --- | --- |
| API 安全回归 | HTML、代理限流、密码重置、跨工作区拒绝 | SQLite / 测试邮件 Provider |
| 浏览器回归 | Playwright 配置、临时测试服务与关键路径 | Node、浏览器二进制 |
| 容器回归 | 多格式提取脚本 | Docker、项目镜像 |
| 恢复演练 | PostgreSQL 迁移/备份/恢复/租约脚本 | Docker、PostgreSQL 镜像 |

提交顺序：先提交本设计；随后提交安全修复与 API 回归；最后提交浏览器、容器和恢复演练。每一提交均执行对应的最小测试、`git diff --check`、推送功能分支；最终 PR 只包含本设计和这组发布回归。

## 9. 可重复执行方式

具体命令、临时资源边界和 CI 调用方式见
[发布运行时回归执行手册](RELEASE_REGRESSION_HARNESS.md)。执行入口为：

```bash
python scripts/run_release_regression.py --all
```

PowerShell 可使用 `scripts/run-release-regression.ps1`。harness 不读取任何生产环境文件，
会在结束时清理自身创建的容器、Docker 网络、临时数据库、命名 uploads 卷和临时镜像。
