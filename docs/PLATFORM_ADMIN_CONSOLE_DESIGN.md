# GreatSell AI 平台管理员控制台设计

**状态：** 已确认设计，按阶段实现与验收

**日期：** 2026-07-21

**适用角色：** GreatSell 内部平台管理员（`is_platform_admin=true`）

**相关设计：** [用户注册、身份与工作区隔离设计](TENANT_ISOLATION_DESIGN.md)、[AI 模型网关与 API 成本追溯设计](AI_GATEWAY_COST_TRACKING_DESIGN.md)

## 1. 背景与目标

GreatSell AI 已具备用户、工作区、三档套餐、AI 路由和调用成本账本。平台管理员需要一个与企业招聘工作台明确分离的内部控制台，用于观察平台运行状态、管理工作区套餐，以及维护平台级 AI 配置。

控制台的目标是：

- 在不接触候选人业务内容的前提下，查看工作区、试用、套餐和 AI 使用情况。
- 通过受控操作调整套餐目录、工作区套餐状态和平台级 AI 路由。
- 为每次高权限变更留下不可变、可追责、无敏感正文的审计记录。
- 为后续收费、订阅、预算和运营支持提供稳定的管理入口。

平台控制台不是“超级 HR 工作台”。平台管理员身份不会自动获得任意租户的简历、候选人、JD、评分、邮箱正文或附件访问权。

## 2. 已确认原则

1. 平台管理员是全局平台身份，与工作区内的 `admin`、`recruiter` 角色相互独立。
2. 所有 `/v1/platform/*` API 都必须在后端校验 `is_platform_admin`；前端隐藏菜单不能替代授权。
3. 平台管理员只能查看运营元数据、聚合指标和脱敏的 AI 调用账本，不能查看任何简历或招聘业务正文。
4. 平台管理员调整某个工作区的套餐，不会把请求会话切换到该工作区，也不会绕过该工作区的数据隔离。
5. 高风险配置采用“显式确认 + 影响说明 + 原因 + 审计”流程；不提供硬删除。
6. Provider 凭据只保存服务端引用。控制台既不接收也不回显真实 API Key、密码或令牌。
7. AI 配置版本、价格版本和路由发布记录保持不可变；新配置只影响后续新任务，不静默改写历史结果或历史成本。
8. 平台控制台与企业招聘工作台共用现有登录会话和同源 API，但使用独立路由、导航和权限守卫。

## 3. 信息架构

平台管理员登录后可进入 `/platform`。普通工作区成员不展示入口，直接访问时显示无权限页；未登录用户仍进入现有登录流程。

```text
平台管理
├── 总览
│   ├── 工作区与试用概况
│   ├── 套餐分布与即将到期
│   └── AI 调用量、成功率、成本状态与异常
├── 工作区
│   ├── 工作区列表
│   └── 工作区运营详情
├── 用户
│   ├── 用户列表
│   └── 账号启用状态
├── 套餐
│   ├── 基础版 / 进阶版 / 专业版
│   └── 价格、试用天数、功能开关与注册可见性
├── AI 管理
│   ├── Provider
│   ├── 模型与价格版本
│   ├── 功能路由与发布历史
│   └── 用量与成本
└── 审计日志
```

### 3.1 总览

总览只提供运营级指标：工作区总数、试用/正常/到期/暂停数量、七天内即将到期试用、用户总数/启用数/已验证数、简历/JD/邮箱数量，以及 AI Run 成功/失败数量、已知成本和成本未知数。

总览不得出现候选人姓名、简历文件名、JD 标题、Prompt、模型回复、邮箱地址、附件或业务资源 ID。所有指标均可跳转到已经带好筛选条件的工作区、AI 用量或审计页。

### 3.2 工作区

工作区列表允许按名称或工作区 ID 搜索，并按套餐和 `plan_status` 筛选。默认列包括：

- 工作区名称和工作区 ID；
- 当前套餐与状态；
- 试用到期时间；
- 启用成员数量；
- 创建和更新时间。

工作区详情仅展示运营元数据、成员安全摘要、当前套餐、试用时间，以及简历、岗位、邮箱和 AI Run 的聚合计数。AI 用量与审计通过各自页面按工作区筛选。详情不得提供候选人、简历、JD、评分、邮箱配置、邮件内容、附件或原文件入口。

允许的首期写操作是修改工作区名称、调整套餐、`plan_status` 和试用截止时间。提交前展示变更前后值、能力影响和试用影响，并要求填写操作原因。暂停、使工作区到期或缩短试用属于高风险操作，需要二次确认；恢复访问和延长试用同样需要审计。

### 3.3 用户

用户页用于处理账号启用状态，只展示平台运营必需的身份元数据：姓名、登录邮箱、是否启用、是否平台管理员、创建时间、最近登录时间，以及工作区/角色的安全摘要。它不展示该用户操作过的候选人、简历、JD 或邮箱内容。

平台管理员可以停用或恢复普通用户账号，操作原因必填。系统禁止停用当前操作者本人，也禁止通过该入口停用任何平台管理员；平台管理员的授予和撤销必须通过独立、受控的线下运维流程完成。首期不在此页面管理工作区成员关系、角色、密码或邮箱验证。

### 3.4 套餐

套餐页维护 `basic`、`advanced`、`professional` 三档目录，展示名称、月价、试用天数、功能开关、启用状态、是否对注册开放、是否为默认试用档位和排序。

套餐编辑采用白名单字段。一次保存必须完整展示功能开关差异；修改默认试用档位时只能保留一个有效默认项。已经开始的订阅和历史试用不因后续目录改价而被静默重算。

### 3.5 AI 管理

- **Provider：** 展示协议驱动、HTTPS Endpoint、当前 API 进程中凭据引用是否可解析、启用状态和更新时间。凭据引用是服务端密钥名称，不是密钥值；Compose 必须将同一引用映射注入 worker，且“已配置”不等同于上游连通性测试。
- **模型：** 展示所属 Provider、供应商模型 ID、能力、上下文上限、输出上限和启用状态。
- **价格：** 只新增价格版本，展示币种、生效区间、计费单位和来源；不覆盖已经冻结在调用账本中的历史价格。
- **功能路由：** 按稳定 `feature` 展示当前版本、目标顺序、最大尝试次数、允许回退的错误类型、Prompt revision 和发布历史。发布前显示影响摘要并要求确认。
- **用量与成本：** 按时间、工作区、功能和模型筛选聚合指标与安全 Run 列表。明确区分 `known`、`partial`、`unavailable` 和 `may_have_billed`，不能把未知成本显示为零。

Provider 连接测试只能使用固定的无候选人测试载荷，不能读取任一工作区数据。测试结果只返回成功状态、延迟、标准错误类别和安全请求标识，不返回厂商原始错误体。

### 3.6 审计日志

审计页按时间、操作者、动作、目标类型、目标 ID 和工作区 ID 筛选。列表项可展开安全的前后差异、操作原因、请求 ID 和时间，不展示密钥、Prompt、候选人内容或邮件内容。

首期不提供审计导出和删除；若以后增加导出，导出本身也必须记录审计事件。

## 4. 权限边界

### 4.1 角色能力

| 能力 | 平台管理员 | 工作区 admin | recruiter |
| --- | --- | --- | --- |
| 进入 `/platform` | 是 | 否 | 否 |
| 查看平台总览和工作区运营元数据 | 是 | 否 | 否 |
| 查看用户运营元数据、停用/恢复普通账号 | 是 | 否 | 否 |
| 调整工作区套餐与状态 | 是 | 否 | 否 |
| 编辑套餐目录 | 是 | 否 | 否 |
| 管理平台 AI Provider、模型、价格和路由 | 是 | 否 | 否 |
| 查看跨工作区 AI 聚合用量 | 是 | 否 | 否 |
| 查看某工作区的招聘业务数据 | 仅在其本身也是该工作区成员时，按成员角色访问 | 按本工作区权限 | 按本工作区权限 |
| 代替其他用户登录 | 否 | 否 | 否 |

### 4.2 后端执行规则

- 匿名请求返回 `401`，已登录但非平台管理员返回 `403 platform_admin_required`。
- 平台 API 使用专门的 `require_platform_admin` 依赖；每个端点都必须显式声明，不允许由前端身份推断。
- `GET /v1/auth/session` 返回 `is_platform_admin` 供前端路由守卫使用；该字段只能由服务端账户记录产生，浏览器不能提交或修改。
- 平台管理权限不受当前工作区的试用到期、套餐状态或功能开关影响；否则平台管理员无法处理到期或暂停工作区。但它仍要求有效、已验证且未停用的平台账号。
- 跨工作区报表只能在平台服务层显式使用 `skip_organization_scope`，并且响应 Schema 必须是无业务内容的白名单。普通业务服务不得复用该豁免。
- `is_platform_admin` 不改变当前 Session 的 `organization_id`，也不使 `/v1/resumes/*`、`/v1/jobs/*`、`/v1/mailbox/*` 等租户 API 跳过作用域。
- 工作区 ID 来自服务端查找结果。变更套餐时，目标 ID 只用于平台操作，不写入当前登录会话。
- 不存在的目标和无权访问的目标使用稳定错误；错误响应不包含数据库结构、密钥引用值或业务内容。

## 5. API 设计

### 5.1 当前可复用接口

```text
GET  /v1/platform/plans
PUT  /v1/platform/plans/{plan_code}
PUT  /v1/platform/organizations/{organization_id}/plan

GET  /v1/platform/ai/providers
POST /v1/platform/ai/providers
GET  /v1/platform/ai/models
POST /v1/platform/ai/models
GET  /v1/platform/ai/model-prices
POST /v1/platform/ai/model-prices
GET  /v1/platform/ai/routes
GET  /v1/platform/ai/routes/{feature}/versions
PUT  /v1/platform/ai/routes/{feature}
GET  /v1/platform/ai/usage/runs
GET  /v1/platform/ai/usage/summary
```

现有接口继续保持平台管理员专用。Run 列表不返回 `business_ref_type`、`business_ref_id`、候选人输入、Prompt 或模型输出。

### 5.2 控制台闭环需补齐的接口

```text
GET  /v1/platform/dashboard
GET  /v1/platform/organizations?search=&plan_code=&plan_status=&limit=&offset=
GET  /v1/platform/organizations/{organization_id}
PATCH /v1/platform/organizations/{organization_id}
GET  /v1/platform/users?search=&is_active=&limit=&offset=
GET  /v1/platform/users/{user_id}
PATCH /v1/platform/users/{user_id}
GET  /v1/platform/audit-events?actor_user_id=&action=&target_type=&organization_id=&created_at_from=&created_at_to=&limit=&offset=
```

工作区和用户列表使用 `limit + offset` 分页。工作区详情响应必须采用专用的 `PlatformOrganizationDetailResponse`，用户详情使用专用安全 Schema，均不能直接序列化 ORM 对象。

工作区 PATCH 的业务字段白名单为 `name`、`plan_code`、`plan_status`、`trial_ends_at` 和必填 `reason`；暂停、设为到期或缩短试用时还必须提交与当前名称完全一致的 `confirmation_name`。用户 PATCH 只允许修改 `is_active` 且 `reason` 必填；服务端拒绝停用当前操作者或任何平台管理员。现有套餐目录和工作区套餐 PUT 接口增加可选 `reason` 以保持旧客户端兼容，控制台始终提交原因。价格发布、路由发布和启停操作同样要求在控制台填写原因并写审计。

Provider 连接测试 `POST /v1/platform/ai/providers/{provider_id}/test` 属于后续 P2 接口，不阻塞首期管理台闭环。首期不新增通用 `PATCH /platform/{resource}/{id}` 或任意 JSON 配置接口。每类写操作必须有明确 Schema、字段白名单和业务校验。

### 5.3 错误与重复提交

- 未认证：`401 authentication_required`。
- 非平台管理员：`403 platform_admin_required`。
- 目标不存在：`404`，使用稳定资源错误码。
- 业务校验失败：`422`，例如默认试用档冲突、无效价格区间或能力不匹配。
- 前端提交后重新读取服务端状态；重复点击期间禁用提交按钮。需要幂等键的发布操作由各自服务保证不重复创建版本。
- Provider 测试、报表和列表失败不得回显上游响应正文、连接凭据或堆栈。

## 6. 数据模型

### 6.1 现有模型

- `user_accounts.is_platform_admin`：平台身份标记；不等同于任何工作区成员角色。
- `user_accounts`、`organization_memberships`：用户启用状态和工作区/角色安全摘要；平台响应不返回密码哈希、令牌或业务活动内容。
- `organizations`：工作区名称、套餐、`plan_status`、试用时间和创建时间。
- `product_plans`：套餐代码、名称、价格、币种、试用天数、功能开关、注册可用性、默认试用标记和排序。
- `ai_provider_profiles`、`ai_model_profiles`、`ai_model_price_versions`：平台 AI 连接、模型与不可变价格版本。
- `ai_route_policies`、`ai_route_policy_versions`：稳定功能路由及不可变发布版本。
- `ai_runs`、`api_invocations`：带 `organization_id` 的安全运行和调用成本账本。

平台控制台读取工作区统计时只能聚合计数和安全账本，不能联表返回候选人、简历、JD、评分、邮箱或文件字段。

### 6.2 平台审计事件

需新增不可变的 `platform_audit_events`：

```text
id
actor_user_id
action
target_type
target_id
organization_id (nullable)
request_id
reason
before_json
after_json
created_at
```

约束如下：

- 只保存字段白名单中的安全差异，例如套餐代码、套餐状态、功能开关、Provider/模型 slug、启用状态、价格版本 ID 和路由版本 ID。
- 不保存请求体快照，不保存密码、Key、Authorization、真实凭据、Prompt、原始模型响应、简历/JD/邮件正文或原文件路径。
- 成功变更与审计事件在同一事务提交；变更未落库时不能产生“成功”审计。
- 被拒绝和执行失败的高权限请求写安全日志，只记录错误类别，不记录原始载荷；`platform_audit_events` 记录已经成功提交的状态变更。
- 审计事件不参与租户数据面过滤，但只允许平台管理员读取；任何租户 API 都不能查询该表。
- 审计记录不可更新、不可硬删除。保留期由平台合规策略统一配置，首期默认长期保留。

## 7. 关键交互

### 7.1 调整工作区套餐

1. 管理员从工作区详情打开“调整套餐”。
2. 选择新套餐和状态，页面展示新增/失去的能力、试用截止变化和影响说明。
3. 填写原因并确认；暂停或到期操作需再次输入工作区名称确认。
4. 后端重新校验管理员、目标当前状态和请求值，在同一事务更新工作区并写审计。
5. 页面重新读取并展示服务端已提交状态；重复点击不会创建重复变更。

### 7.2 发布 AI 路由

1. 管理员选择稳定业务 `feature`，编辑有序目标、尝试次数和允许回退错误。
2. 前端校验重复模型、能力和基本区间，后端执行最终校验。
3. 发布确认展示当前版本与新版本差异、影响的新任务范围和成本风险。
4. 发布创建不可变的新版本并切换活动指针；运行中的任务继续使用已经固定的旧版本。
5. 审计只记录版本和安全差异，不记录 Prompt 正文。

### 7.3 查看 AI 成本

管理员可从聚合结果下钻到安全 Run 列表。`known` 显示已知成本，`partial` 和 `unavailable` 使用明确状态文案，`may_have_billed` 单独提示。页面不提供跳转到候选人、简历或业务记录的入口。

## 8. 响应式与可用性

控制台保持现有深墨、灰、品牌红和桌面端高信息密度风格，不另建一套视觉语言。

- **≥ 1200px：** 展开的深墨侧栏、顶部上下文区和主内容；工作区使用列表与常驻详情的 master-detail 布局，编辑使用右侧抽屉。
- **768–1199px：** 侧栏收为图标轨道，次要表格列进入详情抽屉，筛选器允许换行；工作区详情按可用宽度切换为抽屉。
- **< 768px：** 顶部菜单按钮打开侧栏抽屉；指标卡单列，工作区由列表进入独立详情，详情/编辑抽屉全屏。筛选条件始终保留，不使用底部多图标导航。复杂价格和路由编辑可提示使用桌面端，但不得出现不可退出或内容溢出。

所有页面都必须具备加载、空状态、错误、无权限、部分数据和保存中状态。表单错误与字段关联；键盘焦点清晰；关键按钮触控目标不小于 44px。高风险操作不能依赖颜色或 hover 表达，确认框必须明确写出目标、影响和可恢复方式。

## 9. 明确不做

- 不查看、搜索、预览、下载或导出任何候选人简历、原文件、简历文本、结构化事实、AI 总结、评分、JD、邮箱正文或附件。
- 不提供“以该用户身份登录”、会话接管、租户切换或任何 impersonation 能力。
- 不硬删除工作区、用户、套餐、Provider、模型、价格版本、路由版本、调用账本或审计记录；停用和归档保留历史引用。
- 不在控制台创建、粘贴、读取、回显或轮换真实 API Key、邮箱密码、数据库密码和其他秘密。首期只管理服务端 `credential_ref` 及“是否可解析”的状态。
- 不在首期修改工作区成员关系或角色、重置用户密码、修改注册邮箱或验证邮箱；用户页只允许停用/恢复普通账号。
- 不在首期执行收款、退款、开票、优惠券、支付方式或账单争议处理。
- 不直接运行数据库、Shell、部署、DNS、Caddy、Compose、生产迁移或服务器文件操作。
- 不允许平台管理员代表 HR 作出自动拒绝、录用或候选人沟通决定。

## 10. 测试与验收

### 10.1 权限与隐私

- 匿名访问每个 `/v1/platform/*` 接口均返回 `401`。
- 工作区 `admin` 和 `recruiter` 访问每个 `/v1/platform/*` 接口均返回 `403 platform_admin_required`。
- 平台管理员可访问平台接口，但仅凭 `is_platform_admin` 不能读取其他工作区的任一业务 API 或原文件。
- 工作区列表、详情、用户、总览、AI Run 和审计响应的 Schema 中不存在候选人、简历、JD、邮箱内容、Prompt、模型原文输出、原文件路径或密钥字段。
- 猜测工作区、Run、审计事件和配置 ID 不会绕过平台权限或租户边界。

### 10.2 写入与审计

- 每次套餐、工作区状态、Provider/模型状态、价格版本和路由发布变更都生成一条正确操作者、目标、前后差异、原因和请求 ID 的审计事件。
- 停用/恢复普通用户会记录审计；停用自己或任何平台管理员被拒绝且不会修改账户。
- 要求原因的动作缺少原因时被拒绝；重复提交不会创建重复的价格或路由版本。
- 写入失败时业务数据与成功审计均不落库；重试不会重复创建同一价格或路由版本。
- 历史价格、路由、调用成本和审计记录不能通过 API 更新或删除。
- 审计脱敏测试使用恶意输入验证 Key、Authorization、Prompt 和业务正文不会进入数据库、日志或响应。

### 10.3 AI 控制面

- 禁用 Provider 或模型时，当前路由的有效性由后端校验，不能发布不可执行策略。
- 路由切换只影响新 Run；已经入队的任务仍使用创建时固定版本。
- 连接测试只发送固定无隐私载荷，并对上游错误体脱敏。
- 用量页正确区分已知、部分、未知和可能已计费成本；未知成本不会被计为零。

### 10.4 前端与响应式

- 普通用户看不到平台入口，直接输入 `/platform` 显示无权限且不会发出平台数据查询。
- 1440px、1024px、768px 和 375px 视口下无不可达操作、遮挡或页面级横向溢出；数据表的局部横向滚动除外。
- 加载、空、403、404、422、500 和网络重试状态均有可理解的中文反馈。
- 套餐调整与路由发布的二次确认、键盘操作、焦点顺序和关闭恢复状态通过自动化浏览器测试。

### 10.5 发布门槛

- 平台 API 权限矩阵、跨租户业务 API 回归、审计脱敏和重复提交测试通过。
- 后端完整 `pytest`、前端 `npm run build`、前端组件/Playwright 关键路径和 `git diff --check` 通过。
- 迁移只新增平台控制面所需表/索引，不读取或移动候选人文件，不接触生产密钥。

## 11. 后续订阅模型

首期继续使用 `organizations.plan_id + plan_status + trial_started_at/trial_ends_at` 完成人工套餐管理。接入支付时，订阅必须作为独立领域引入，不能把支付状态直接塞进套餐目录，也不能通过覆盖套餐价格改写历史账单。

建议后续新增：

```text
product_plan_price_versions
  plan_id, currency, amount, billing_interval, effective_from, effective_to

subscriptions
  organization_id, plan_id, price_version_id, status,
  current_period_start, current_period_end, cancel_at_period_end,
  billing_provider, provider_customer_ref, provider_subscription_ref

subscription_events
  provider_event_id, organization_id, event_type, occurred_at,
  payload_hash, processing_status, processed_at

entitlement_snapshots
  organization_id, subscription_id, plan_id, feature_flags,
  effective_from, effective_to, source
```

后续原则：

1. 支付 Webhook 以 `provider_event_id` 幂等处理，原始支付载荷和支付方式不进入平台控制台普通日志。
2. 套餐目录负责售卖定义，价格版本负责历史价格，订阅负责客户生命周期，Entitlement 负责服务端功能授权；四者不混用。
3. `trialing`、`active`、`past_due`、`canceled` 等订阅状态映射到清晰的访问策略，并提供宽限期，不能因一次支付回调异常立即删除或暴露数据。
4. 工作区管理员未来只查看自己的套餐、账单状态和升级入口；平台管理员查看跨工作区订阅元数据，但不查看完整支付凭据。
5. 退款、开票、优惠券和税务规则在支付方案确认后单独设计，不在当前控制台中预留假的可操作按钮。
6. 套餐或价格调整、人工赠送时长、暂停/恢复订阅都必须写入平台审计，并与支付 Provider 事件区分来源。

## 12. 分阶段交付

1. **P0 — 只读骨架：** 平台路由守卫、总览、工作区列表/详情、套餐与 AI 配置只读页。
2. **P1 — 受控运营：** 套餐编辑、工作区套餐/状态调整、Provider/模型档案、价格版本和路由发布。
3. **P2 — 审计与可靠性：** 平台审计事件、重复提交保护、连接测试、错误与脱敏回归。
4. **P3 — 成本与预算：** 用量下钻、预算预警和额度控制；普通工作区仍不获得模型选择权。
5. **P4 — 订阅：** 价格版本、订阅生命周期、支付 Webhook、Entitlement 和工作区自助续费。

每一阶段都必须保持租户数据面隔离。平台功能增加不构成访问候选人数据的理由。
