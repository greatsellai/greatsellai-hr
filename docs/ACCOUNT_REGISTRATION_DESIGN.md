# 账户注册与邮箱验证设计

## 目标

把当前“创建账号后直接进入工作台”的流程改为可运营的自助注册闭环：用户创建独立工作区，收到一次性验证邮件，验证邮箱后才可以访问候选人、简历、JD 和 AI 能力。每个成功验证的新工作区获得 30 天进阶版试用。

本设计只覆盖注册和邮箱验证。找回密码将复用同一邮件发送接口和一次性令牌约束，在下一项工作中接入。

## 用户流程

1. 用户在 `/register` 填写企业或团队名称、姓名、工作邮箱和密码。
2. 服务端创建用户、独立工作区及管理员成员关系，工作区不含任何其他租户的数据。
3. 服务端生成仅保存摘要的一次性邮箱验证令牌，并向该邮箱发送验证链接。
4. 浏览器显示“请验证邮箱”页。未验证账号可以重发验证邮件或退出，但不能访问业务 API。
5. 用户打开链接，前端将令牌提交到验证接口。服务端核验令牌、写入 `email_verified_at`、建立会话，并进入工作台。
6. 30 天试用从注册时开始计算，验证是进入工作台的前置条件，不会让用户因等待邮件而丢失额外试用时间。

## 安全与隔离

- 验证令牌只以 SHA-256 摘要存储，原始令牌只存在于本次邮件链接中。
- 令牌 24 小时失效、仅可使用一次；重发会废止之前未使用的令牌。
- 重发对同一账号设置冷却时间和每日上限，避免被用作邮件轰炸工具。
- 会话中继续保存用户、成员和工作区三元身份。所有业务 API 在原有工作区隔离后，再要求邮箱已验证。
- 旧版迁移工作区和既有平台兼容登录不受此门禁影响，避免锁住历史数据。
- 邮件验证接口不返回其他用户、工作区、简历或候选人信息。

## 邮件服务

外发验证邮件与收取简历的 IMAP 是两套服务。生产采用腾讯云 SES API：

- 发件域建议使用独立子域，例如 `mail.greatsellai.net`。
- 使用腾讯云审核通过的事务邮件模板，模板变量为 `verify_url` 和 `expires_minutes`。
- 应用从环境读取 Provider、发件地址、公开应用地址、SES 区域和模板 ID；密钥继续只通过环境变量提供，绝不写入仓库或数据库。
- Provider 未配置或发送失败时，注册不会获得业务访问权，页面会明确提示重发或稍后重试。

## API

- `POST /v1/auth/register`：创建待验证账号与工作区，建立仅用于验证页的会话，并发送验证邮件。
- `POST /v1/auth/email-verification/complete`：兑换验证令牌并激活工作台访问。
- `POST /v1/auth/email-verification/resend`：当前待验证会话重发验证邮件。
- `GET /v1/auth/session`：新增 `email_verified` 和 `email_verification_required`，前端据此显示验证页而非工作台。

## 验收与回归

- 注册创建的新工作区与其他工作区完全隔离。
- 未验证会话无法读取、上传或匹配任一业务数据。
- 正确令牌只能使用一次；过期、篡改或已废止令牌均不能激活账号。
- 重发遵守限频且只保留最新有效令牌。
- 邮件发送调用不记录令牌、密码、候选人信息或密钥。
- 旧版兼容工作区、已验证账号、登录、试用与跨租户测试继续通过。
