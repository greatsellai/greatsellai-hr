# 运行诊断与日志手册

## 目标

本项目的运行诊断用于定位请求、后台任务、模型调用和代理故障，同时不得把候选人隐私、邮件正文、简历原文、模型 Prompt、Cookie、授权头或任何凭据写入日志。

应用以 JSON 事件写入 stdout。Docker 为每个服务保留最多五个 20MB 的本地日志文件。该本地保留只用于短期排障，不能替代异机日志保留。

`/health` 仅用于进程存活检查；`/readyz` 会执行一次不带业务数据的数据库查询，仅在 API 和数据库均可用时返回 `{"status":"ready"}`。兼容入口对应 `/greatsellhr/readyz`。这两个端点均不返回配置、租户或候选人信息。

## 诊断编号

每个 HTTP 请求都有 `X-Request-ID`。前端出现失败时应记录并向用户展示该编号。平台管理员可以用以下任一安全标识关联排障信息：

- `request_id`：一次浏览器或 API 请求；
- `job_id`：一个后台解析、总结、匹配、评分或邮箱任务；
- `ai_run_id`：一段 AI 功能运行；
- `provider_request_id`：模型服务商返回的请求编号。

这些标识不是候选人内容，仍只对受控管理员可见。

## 允许记录的字段

- 事件名、级别、时间、组件、发布版本；
- `request_id`、`job_id`、`ai_run_id`、`workspace_id` 等内部不透明 ID；
- HTTP 方法、路由模板、状态码、耗时；
- 任务类型、尝试次数、队列状态、标准错误码；
- 模型服务商 HTTP 状态、耗时和 `provider_request_id`；
- Worker 心跳、队列积压、最老等待时间。

## 严禁记录的字段

- 简历正文、候选人姓名、邮箱地址、电话、文件名、邮件 RFC822 内容；
- 模型 Prompt、模型完整输出、请求/响应原文；
- Cookie、Authorization、API Key、密码、数据库 URL、OAuth token；
- HTTP 请求体、查询参数和完整客户端 IP。

未知异常只保存标准错误码、异常类别和经过筛选的代码位置。不得把第三方返回正文或原始异常消息直接写入日志或任务错误字段。

## 内测排障路径

1. 先在平台“运行诊断”查看 API 就绪、Worker 心跳和队列积压。
2. 若是用户接口失败，使用响应中的 `X-Request-ID` 查安全事件。
3. 若是异步任务，按 `job_id` 查看状态、尝试次数、错误码与最近处理时间。
4. 若涉及模型调用，按 `ai_run_id` 或 `provider_request_id` 查看模型服务状态、延迟和失败类别。
5. 若 API 就绪但 Worker 心跳过期，优先检查 Worker 容器日志和部署状态；不要通过重新上传候选人资料来“试错”。

## 腾讯云日志保留

生产运维在腾讯云 CLS 创建一个日志主题后，为 API、Worker 和 Caddy 的 stdout 配置采集。建议：

- 初期保留 30 天；
- 仅允许平台运维成员访问；
- 按 `event`、`level`、`request_id`、`job_id`、`ai_run_id` 建索引；
- 不采集 Docker 环境变量、数据库卷或上传目录；
- 配置 API 5xx、Worker 心跳过期、失败任务连续增长、队列等待过久和磁盘使用率告警。

CLS 的创建、角色授权与费用归属属于云资源操作，需由具备腾讯云权限的负责人执行。本仓库只保证 stdout 事件的结构和本地轮转策略。
